# 数学探索：结构、活动与证据

## 2026-11-14｜分数运算中的单位、构造与工具输出（Issue #150）

10道原生分数四则题先保留估计，再完整表示两个原量。加减核对同样大的小份及实际选择，点击合并/拿走后的结果条明确由工具生成；乘法核对真实行列选择与交集小格面积，不把不连续的选择冒充连续长方形，也不把工具交集称为孩子独立构造的结果。除法分别描述当前有效的整组数、原单位中的余量及余量占一组的比例，不能把两种分数单位混用。

合法的错误估计、涂擦、换共同分母、重复确认和重置可以保留。空选择、原工具未接受的等值形式或公分母、未摆齐就接合或放组、放满后再试一组、提前查看余量，均按原工具真实结果保留为未完成请求：完整28字段、失败前后相同构造和原提示逐一核对，不计作成功构造。后来实际纠正或重置后完成，可核对新作品；空选择不算一次估计，首次真正有内容的选择才是最初估计。重置不清空历史、最初估计或已写字段，改变共同单位或涂份会使此前分组/接合失效，当前事实只引用最后失效之后的有效步骤。

完整构造后多点一次放组，原题仍可能判定正确；只要最新完整提交匹配，失败留下的提示与实际事件逐字相符，就保留失败并描述已有构造，不要求提示人为清空。手动抹掉提示、不可见按钮事件、错误身份、过期提交和数值舍入造成的假整数仍不能成为严格证据。原判题、评分与继续作答不变。

可选问题不提前给答案；严格反馈要求当前完整作品等于最新提交、原判题成功和独立精确回放同时成立。3个来源均不授予MP标签，不评价自由解释、独立证明或长期掌握。中性核心事件索引可供之后独立审核的包装题复用，当前不为B18额外要求或自动预测归因作保证。真实Chromium、独立教研与儿童使用分别记录，本地源控件探针不替代浏览器验收。

## 2026-11-14｜P9 几组、几颗与分数名称（Issue #140）

13道分组取分数题把“物品怎样分放”“选了几组”“选了多少颗”分别核对。每颗物品保留原身份；每次分放后，各组里的物品加上尚未分放的物品，总量保持一致。已选与未选的物品共同构成原整体，不能把未选中的数量误作分母，也不能在守恒核对时把组内未选物品再加一次。

实际把12颗分成4组、选1组时，按组是1/4，按物品是3/12；提交2/8也可表达同一比例，但不表示孩子实际分出了8组。反馈明确标为“提交的分数”，保留实际组数与物品数。等式只说明当前提交与分组数量相符，精确有理数核对不把填写等式冒充一次独立计算或证明。

取组按钮可以先于分放使用，孩子也可暂时分得不均等、再把原物品移到其他组。反馈描述最终作品与真实事件，不替孩子补出“先平均分再取”的固定顺序。重新摆会清空棋盘，但保留字段和旧事件；无作用放置不能通过reset洗成严格证据。提示仍可选，只有最新完整提交与当前作品一致且数学回放成立时显示观察；编辑立即收起。全部method:null，不自动评价自由解释、独立计算、迁移或长期掌握；20道关联题维持独立归属。

本准备分支随估算与角度检查点同步正式main b81，并将分组取份的真实双视口验收接入第二扩展组。七组调度不改变实际组数与提交分母的区别、物品守恒、提前取组或reset保留历史的边界；全部原作答及P10路径仍在最终HEAD分别验收。

## 2026-11-14｜P9 估计记录与检验范围（Issue #138）

24道估算题的唯一事件是保存一次舍入和粗略结果。反馈不能据此虚构精算步骤或独立逆算操作；只描述实际估计记录及当前提交的等式。系统按所选间隔推得区间，加法左闭右开，减法两端开，并明确范围不是孩子自行构造或证明的证据。

412+389的粗略结果800可能落在估计范围内，但精确答案为801；合理估计与精确正确必须分别说明。预先误差保证取决于所选间隔，不能以一次碰巧接近替代。错误舍入后改正仍保留原作答功能及全部记录，但不把这段有无效事件的历史归入严格证据；孩子的自由解释与长期掌握保持未自动评价。

本准备树依赖 #148 与 #154，验收和合并状态见 Issue #130。七组调度不改变唯一估计事件、范围由系统生成、逆算仅为提交等式的证据边界；所有原生/关联隔离与完整 P10 仍须在最终 HEAD 验收。

## 2026-11-14｜P9 加减情境的演示证据（Issue #148，本分支）

41道原生题的严格反馈只描述已记录的演示快照与交换、以及最新提交的算式。两部分数量和所选动作来自演示发生时的记录；合并结果、划去与配对图由系统生成。数量按钮、符号修改、逐颗身份和未成功点击没有完整轨迹，不能据此声称还原了每次操作、逐个计数或孩子独立计算的过程。

未知数题先辨别猜想框问的是原来的一堆、另一部分还是结果。首次猜想与本题所求的量核对，也单独说明中间探索的数量；对2+1猜3成立，不因本题最后要演示3+2就说那次探索算错。重复演示只表示又请求过相同数量/动作，不能证明未记录操作期间画面从未变化。

零变化如实说明增加或取走0个。比较图说明系统配对与未配到的部分；等量题另一侧明确是工具给定的参照。交换减法后的不足描述当前可用数量、所需数量与缺少的数量，绝不制造负数量物品。手指图超过五指或需要非零划去、配对图与所选加法不一致、直接取走超过可用数量等历史不能被后来的正确演示抹掉；原题判定与历史仍保留。

严格反馈须同时满足真实原生来源与完整题目指纹、独立数学回放、原判题正确和最新完整提交一致。改动后收起旧反馈；全部method:null，包含已有MP课程来源。真实正例helper从空模型按原有可见控件构造，隔离原示例中互斥隐藏字段的人工填充，不改原模型/示例/评分/v2格式。独立教研、儿童与Mac人工验收另行记录。

## 2026-11-14｜P9 开口记录与角关系（Issue #136）

23道角度题通过set、quarter、length、record记录核对具体开口。指定一个开口不能据此声称孩子完成连续转动，board.first也不是预测；边长1/2/3只是短中长等级。反馈分别说明短边/长边时同角记录、指定目标记录间的差与当前交叉线关系。目标之间可保留合法探索记录，例如实际留下65°、100°、180°时，本题指定的差仍为180°−65°，不能称为相邻记录之差；不虚构独立推导、构造三角形或一般证明。

271…359的quarter按钮实际只接到360，文字改为所剩角度；360则说明到下一圈的四分之一位置。0与360保留不同记录含义。合法同值set只是确认，重复record不能成为新证据；当前角或输入脱离已记录关系时收起旧反馈，仍保留原作答和保存规则。

本准备分支已通过transform `755ad4568a88bc7461f0b829efbefc0b8354bd1e` 同步正式main `b81ac628b85f981a40bc2749d713e39492b2c89e` 的分组与数值兼容保护。角度、分组、变换在第二扩展组各执行一次真实浏览器验收；CI分工不改变数学证据、普通完成或学习状态的边界，未通过自身最终HEAD验收前不计为交付。

## 2026-11-14｜P9 变换参数与工具生成的坐标（Issue #135）

23道原生变换题的反馈核对实际预测、选择的参数与工具生成的对应点。每次operate都从原始图形出发，不将多次试验说成连续复合变换。边长平方、角与反射方向用精确有理数验证；单点活动不宣称边长或角证据。工具的measure按钮只显示读数，反馈明确没有据此评价独立量取、独立作图或一般证明。

错误初猜与后续正确操作分开描述。非法参数后修正、重复无作用变换、无图量取、精度舍入和跨控件历史不能洗成严格证据。来源与最新提交门槛保持；普通任务完成、P10保存与数学反馈的解释范围分别验收。共享解析缺陷及旧记录兼容已由#139正式修复；本项以真实负数和分数参数验证坐标及图示，不借存储兼容赋予数学正确性。

## 2026-11-14｜P9 分组、平均分与答案含义（Issue #133）

29道原生题通过真实物品身份与容器记录核对分放。建立等份时，总量由实际加入的物品形成；平均分或按每份量分组时，原有物品守恒，不凭最终答案虚构分配步骤。反馈明确答案表示“总量”“每份数量”还是“份数”，并分别说明5份空容器仍合计0、单份和真实余数。移动次数包含来回修改，不能当成物品总数；选择或加容器也不能冒充一次分放。提交算式可在符号两侧留空白，分开的数字不能由系统擅自拼接成另一个整数；纠正写法后仍需重新检查当前作品。

引导默认可选且不提供答案。反馈只在当前完整作品与最新提交一致、原判题正确且独立数学回放通过时出现；编辑后立即收起。保留原任务/评分/保存与进度，不评价自由解释或长期掌握，全部来源method:null。独立教研与儿童使用仍需分别记录。

## 2026-11-14｜负带分数与旧作品的解释界限（Issue #137）

数值中的负号属于整个带分数，`-0 1/2`应为负二分之一。共享解析与预测点绘制采用一致的数值含义。历史错误解析所形成的作品可原样读取和导出，但不能借存储兼容被重新认定为正确过程、当前完成或严格证据。

遇到这种旧当前作品时，界面保留查看并说明原因。先发起完整v2备份导出，使用者确认保留文件后再明确重做；只有这一操作会按已有重做语义替换当前草稿，已提交的尝试和文字记录保留。界面不把发起下载称为文件已经落盘，也不自动更改历史数学操作。

## 2026-11-13｜任务性质、评分证据与节点进度的设计界限（PR #84 后）

> 当前**设计约束与待决策事项**；不改变代码中已经生效的判题、通关、数据保存规则。以 [587 节点审计](LEARNING-NODE-AUDIT.md)、[Issue #82](https://github.com/runlinx-eng/math/issues/82) 的逐 ID 证据和最新 CI Artifact 为依据。下文较早的“可选”统称不应被当作“独立评分可选题”。

**四类性质要分开。** A「核心题」是原生课程内必须按现有检查规则通过才能进入下一步的题，现共 1,996 道。B「可选评分练习」是有独立任务、判题和保存证据，却不阻塞单个节点核心完成的练习；现有 776 组联合任务共 1,552 道是重要候选来源，但其节点归属仍待确认。C「知识探索与导航」包括前置/后续节点、短路线、资料、地图关系、课程跳转，不能按题目完成计数。D「非评分学习记录」包括可选发现、总结、文字反思与未提交草稿；存在或缺失不决定核心通过和第四级。重做原题不是新增可选题；切换原生课程中已有任务可能仍是核心题。

**审计的准确结论：** 587 个原生课程内部独立评分可选题为 **0**，但整个数学树并非没有额外可评分练习。联合任务自己的 session、题目、判题、保存记录与节点原生核心题分离。视觉上的「其他探索（可选）」「换个办法或看看联系（可选）」混合重试、其他核心条件、后续课程、知识导航、联合任务和个人文字，不能据栏目标题判定分母。旧 `PRACTICE[-1]` 自由试玩不是新的独立评分题。

**2026-11-13 已确认的进度显示规则**：一级无有效保存作答；二级有至少一次已保存的有效提交（答错也算），但核心未全完成；三级原生核心全部按照既有判题通过，**点亮第三级光**；第四级设想为核心与归属本节点的全部可选评分练习均完成，但**第四级光暂不启用**，不因原生可选题为零、联合任务完成或无可靠归属而推断最高级。旧成功快照不能冒充修改后尚未重新检查的作品已通过；页面访问、导航、草稿、文字总结、两个关联节点各自完成均不产生联合任务的通过证据。

**历史保全**：三个早期活动 `fair`、`rename`、`decimal` 的旧 construct/transfer 完成条件是各类有提交，不等于原生核心检查通过。现仅确认为规则差异，实际核心阻塞严重性为待核查，不能错误标成 P1；无历史记录时 `fair` 独立入口未显示的实测属 P2。旧提交、正确/错误、联合任务 `daily.bridges`、备份、提示、草稿均保留；不重写旧存储格式，不因归属未决就覆盖或重复计数。无法可靠判定的历史状态保留内部待核查。

**仅第四级及历史解释仍待用户决定、未批准为实施规则**：联合任务属于起点/终点/双端/独立边中的哪一方；涉及两个节点和多个联合练习如何计数；各节点数量不等时第四级分母如何定义；确认没有 B 的节点是否核心完成即最高级；旧活动提交与通过如何合并解释；新增可选练习时已达最高级节点是否重新计算及如何展示历史；无法判定旧记录如何保守呈现。不得凭工程方便自动选择其一。试点须先对源节点 ID、source edge ID、bridge session ID、task index、完成记录做只读归属表和去重模拟，并检查备份/恢复、旧错误提交与当前作品。

**实施顺序**：Issue #85 先完成只读归属试点、前三层派生状态及兼容回归；前三层显示与第三级光可作为独立小 PR 开发，**不等待联合任务归属**。第四级光继续关闭，待未来确认归属规则和兼容证据后独立开发。

### 1. 唯一学习主线

**发现/选择知识 → 明确当前问题 → 观察、猜想与操作 → 检查作品 → 根据反馈修正或解释 → 换条件/建立联系 → 保存证据、回到同一数学空间。**

- 默认从 3D 选中知识、待续问题或足迹恢复后，**直接进入可操作的当前任务**，首屏就呈现任务要求与教具，不需要先「自由试玩」再「开始第 1 题」的额外门槛。
- **不再有「自由试玩／正式任务」模式切换**。孩子在同一教具中自由观察、猜想、摆弄、修改、提交；只有显式「检查我的作品」才记录一次提交。自由操作无需进入别的页面或模式，也不会因为摆弄而被计为完成。既有旧版 `play` 记录和其 `models[-1]` 作品须无损保留并能回到统一学习现场，不删除旧备份。
- 允许随时留下问题、暂停、返回 3D、切换学习/足迹，再接续原现场；不强迫完成全部任务才能离开，也不强迫按知识关系的箭头依次学习。
- 某个知识没有配置合适活动时明确告知「暂无可操作任务」，仍可查看真实知识联系和留下问题；禁止用占位题冒充有效学习任务。

### P7-D5｜顶部「学习」的入口决策（2026-11-09）

顶部「学习」是进入现有学习现场的操作，不是必经的学习功能菜单。入口按真实来源和已保存数据做决定，不修改学习任务、判题、源关系或相机：

1. **已明确选中知识点**：以该节点对应的真实配置活动为准，直接打开统一学习工作区；同节点已有作品/尝试/草稿时由原运行器恢复。既有早期独立活动与早期路线可直接进入其原入口。其他节点的历史记录不得覆盖当前选择。
2. **未选中具体知识**（含只选知识群/主题）：仅当存在可恢复的未完成学习现场时突出「继续上次学习」，否则只突出「选择一个知识点」。空白会话、已完成记录、推荐路线均不冒充待续任务；没有理由时不随机指定节点。
3. **没有可执行活动的节点**：明确提示没有独立操作活动，保留知识观察、真实关系、现有搜索和按需入口；不得显示无效的开始按钮或伪造关联学习。
4. **次级能力**：短路线、历史足迹、查找与早期能力仍可访问，放在非竞争性的按需区域。进入学习无需先选路线，也无需重新学习工作区的主要操作。
5. **操作和状态**：切换视图不改变 3D 相机、节点固定坐标或学习状态；返回原知识位置。刷新、浏览器历史、重复点击不得无故重置学习现场；保存文字不是强制完成门槛。

**验收分层**：Node 入口决策与 Chromium 真实按钮/截图仅证明工程路径；Mac 100% 缩放人工实际体验、儿童独立使用与教学效果须分别记录，未验证不得标记完成。

### 2. 同一个任务的状态机

主流程只有以下任务状态。提示、自由操作、保存、空间导航属于同一学习现场的横向能力，不另建一套试玩模式或课程导航。

| 状态 | 进入条件／孩子看到什么 | 当前最重要的操作 | 状态转换 |
| --- | --- | --- | --- |
| **待操作** | 新开或恢复任务，显示当前知识、要解决的问题、必要条件和实际教具；未提交就不显示空的历史统计 | 直接操作教具；若活动要求先预测，则先填写预测 | 第一次有效操作进入「操作中」；也可随时暂停或看提示；没有单独的试玩入口 |
| **操作中** | 当前作品/预测/解释正在改变，保留明确任务要求、可辨操作区域及必要进度 | 操作、补齐条件；满足当前活动检查条件时「检查我的作品」成为主动作 | 真正提交才产生一条尝试；未准备好时说明还需做什么，不用神秘的禁用按钮 |
| **需要修正** | 已提交的当前作品未满足既有判题条件，显示**哪一处**需要修改及可理解的原因 | 修改作品并重新检查，不要求先走另一个「重试」页面 | 修改后进入操作中；旧检查留在历史但不冒充新作品已经验证；再次提交生成新尝试 |
| **本题通过** | 提交快照符合当前任务的既有检查条件，清楚标为「这次检查通过」而非「已掌握」 | 有下一题时「进入下一题／换条件」，没有时「整理这次发现」 | 可继续、回看、换方法或重试；重新修改当前作品后，不把旧检查当作修改后作品的检查结果 |
| **整理与接续** | 已满足本次任务组原有完成条件；展示此次真实发现、尝试与可选解释 | 保存/确认自己的文字发现（有内容时），然后「回到数学树继续探索」或依据真实关系继续 | 返回同一 3D 场景，足迹可恢复；可选迁移与联合活动不自动计为已完成 |

**约束：** 状态来自当前有效任务、作品、提交尝试、已配置完成规则和已有保存内容；不得引入第二个与原记录冲突的「进度真相」。若某个复杂活动有「观察→预测→构造」子步骤，子步骤由该活动自己控制，不新增外层页面级状态。

### 3. 每一刻只有一个主目标

- 「主操作」是当前最值得注意的**行动意图**，不一定是按钮。刚进入时可以是拖动纸带、摆放点或选择依据；准备检查时才突出检查按钮。
- 未开始操作时不把「下一处」「换个条件」「切换试玩」「历史记录」并列成多个主按钮。
- 错误后优先展示具体改法与原教具；不要把错误转成必须退出、重开或清空作品的步骤。查看提示属辅助操作，使用过提示必须照实记录。
- 通过后突出**下一题或整理发现**，避免继续将「检查」和「下一题」同时作为两个主按钮；当前检查通过不等于整个知识点掌握。
- 关系追踪、路线列表、作品历史、实践应用按需访问但不抢任务焦点；自由观察和操作属于主任务现场本身，不需要专门打开。
- 任务、操作、检查、反馈、下一步在阅读方向上形成因果顺序；不允许用反馈替换任务说明，也不允许把结果反馈埋到冗长的历史统计下面。
- 操作长于视口时，保证主操作与最近反馈**容易被找到**（例如同一操作区域内的定位或必要的吸附操作区），不允许宿主面板和 iframe 双重不可控滚动，也不为布局截断教具。

### 4. 学习反馈必须与真实证据一一对应

| 反馈层次 | 可使用的事实 | 不允许推断 |
| --- | --- | --- |
| **作品结果** | 哪次提交、哪组条件、哪些检查点满足或未满足既有规则 | 「已经掌握整个知识」 |
| **过程轨迹** | 实际操作、首次错误、修改、查看提示、重试、提交、草稿和文字原话 | 未采集到的心理活动或解释能力 |
| **思维方法线索** | 已定义、可复核的具体行为，例如主动构造反例、保持整体不变并重分、为结论选择理由 | 只因答对就标记「论证与质疑／建模／找规律已掌握」 |
| **长期成长与迁移** | 不同知识和新条件下，多次可核对的行为及必要独立教研 | 一题正确、一段自由文字或一次浏览就生成能力等级 |

- 每次检查反馈必须绑定**当时提交的作品快照**。后来修改，旧结果进入历史；当前作品若尚未重检，应显示「已修改，尚未重新检查」，而不是继续给它显示通过/失败结论。
- 自由输入和口述若没有可靠的语义核验能力，只存为「我的解释（待确认）」，不自动评懂。思维反馈可描述具体动作的可能方法，但必须说明观察依据，不给虚假思维分数。
- 发生保存失败、无法检查或离线不可用时，明确说明当前状态并保护原记录；不显示虚假「已保存」「检查通过」。真实模拟与真实生活实践继续区别。
- 不因一次提示后正确抹掉第一次错误，不因后来做对擦掉独立性/提示证据；历史记录可折叠但绝不丢弃。

### 5. 学习工作区与 3D 空间的职责边界

| 层 | 唯一职责 | 禁止 |
| --- | --- | --- |
| **3D 空间与外层工作区** | 显示当前知识、真正的数学关系、空间位置；统一「探索／学习／足迹」、挂载/收起活动、返回和状态恢复 | 在学习中自动挪动镜头/选中，另建第二张关系图；与内部运行器重复导航 |
| **活动运行器** | 展示当前任务、专属教具、输入、检查、即时反馈、局部重试及本次解释 | 再提供一套全局「探索／学习／足迹」和多层进入退出 |
| **学习记录与足迹** | 按原 v2 数据保留草稿、完整尝试、提示、检查、作品、问题、接续和备份 | 从 UI 点击、查看关系或单次正确猜测出掌握状态 |

同一知识从探索进入、从关联活动进入、从足迹返回或刷新恢复，必须尽可能保持同一 session、任务索引、未提交作品、历史提交与原 3D 选择/相机。外层 3D 镜头状态与内层学习证据分开保存。切换工作区是**暂时收起学习现场**，不是自动完成、交卷、清空或放弃。

### 6. 一套流程，不强制一套教具

具体活动可以是操作型（分份、积木、数轴）、观察/调查型、猜想检验型、推理/反例型、文字解释型或跨知识联合型。每种活动接入统一工作区，只需明确：

1. **当前问题**：孩子要研究的量、关系、事实或猜想。
2. **可见操作与完成检查的必要条件**：哪些动作/输入/观察属于这项任务，何时可提交。
3. **任务专属检查与解释**：仍由既有模型和 inspect 规则定义，可有多种有效作品。
4. **检查后下一动作**：修正、继续观察、换条件、总结，或连接真实已收录的来源关系。

不要求每项任务都有三题、独立试玩模式、必填反思或数值自动判题；不为统一交互重写现有 1,996 项有限任务。已有活动缺少适合的「准备检查」信息时，先做任务映射/有界适配，不能凭标题猜测数学判题规则。

### 7. 用「等值分数」判定流程是否清楚

1. 选中「等值分数」，活动直接显示「把三条一样长的纸带各涂出一半」，同时可操作 1/2、2/4、3/6 的纸带，**无需先试玩再切到任务**。
2. 孩子改变涂色份数后，检查按钮与教具紧邻；第一次不对时指出哪些纸带的**末端未对齐**、应比较同一个整体，旧操作不被清空。
3. 修正后再次检查。通过时提示「这三种分法表示的涂色长度相同」及可选追问「为什么切得更细，得到的量没有变？」；不给「已掌握论证」标记。
4. 孩子可继续换一组分法、保存自己的解释、访问真实关联知识，或直接返回原 3D 位置。退出后重新打开，草稿、提示与错误尝试仍在。
5. 若孩子独立给出数学理由，可以在有真实记录和适合核验方法的条件下做**有依据的过程反馈**；自由文字不因存在就自动评为正确论证。

### 8. 验收门槛与后续实施顺序

- **第一屏**：选中已有活动的知识后，直接看见当前问题、教具与可执行操作，并可在**同一现场**按条件直接检查，不经过「进入试玩→开始任务」的模式切换；初次进入不呈现空证据墙。
- **状态主次**：待操作、有效检查前、错误、修正后未复检、通过、总结六种可见状态各只有一个明显主目标；无效操作应有可理解的原因。
- **数学证据**：每次提交/提示/重试与显示结果一致；检查绑定快照；修改后不沿用旧结论；单次正确不判定掌握；联合活动只沿真实源关系。
- **连续恢复**：关闭、暂收、切学习/足迹、刷新、离线、旧版 play/task/summary、坏存储、备份恢复均有对应回归；绝不清除旧作品或移动 3D 相机。
- **实机验收**：至少操作型、推理/解释型、联合型各一条真实任务，覆盖 1440×900、紧凑视口和长操作区。截图/Chromium 与 Mac 人工、孩子独立操作、数学教研分别记结论，不相互替代。
- **分轮实施**：先在现有任务模型上建立派生的可见交互状态与主操作选择；再处理入口默认正式任务、反馈快照与原位修正；然后打通接续及多类型回归。**本规范 PR 仅形成规则，不顺带修改运行器。**

### 9. P7-D1/D2｜统一学习面板已实现的结构和边界

**固定结构（仅一个学习现场）**：

| 公共区域 | DOM / 责任 | 运行时变化 |
| --- | --- | --- |
| 要解决的问题 | \`#learning-problem\`、\`#instruction\` | 显示当前知识对应的**实际任务提示**；检查结果不覆盖任务问题 |
| 动手探索 | \`#learning-interaction\`、\`#work\` | 按现有活动类型渲染纸带、数轴、积木、调查、推理、文字输入；保留原作品和事件 |
| 检查与反馈 | \`#learning-check\`、\`#actions\`、\`#check-feedback\`、\`#math-explanation\` | 显式检查产生记录；错误提示可修改，变更后需重检；正确后只有一项主去向 |
| 发现与继续 | \`#learning-next\`、\`#p3-learning-flow\` | 总结/保存后回到 3D；历史、其他条件、知识关系和模拟实践按需展开，不再与主按钮平级 |

**状态**由 \`dist/learning/workspace-flow.js\` 根据已有学习记录与 \`currentSubmission()\` 派生：\`explore\`、\`revise\`、\`recheck\`、\`passed\`、\`reflect\`。它不拥有新存储字段、判题规则或第二份进度。页面主操作仍由原活动实际完成条件决定；错误、提示、草稿和历史结果不被覆盖。

**标准样板——等值分数**：

- 纸带题：通过时解释本次提交的 \`2/4 = 3/6 = 4/8 = 1/2\`；未通过时依据该次提交指出哪条纸带没有与同一半份对齐。
- 数轴题：通过时展示 \`2/3 = 4/6\` 或 \`2/3 = 6/9\` 并说明为什么两个标记属于同一整体和相同位置。检查后若重新修改，旧证明不再显示为当前作品结论。
- 最后一题通过后的唯一主操作是「整理这次发现」。文字发现为可选；已经输入内容时突出保存，保存后突出「返回知识空间」。完成题目不代表独立掌握推理。
- 任意关联/其他条件/模拟实践不自动产生真实生活实践证据；继续使用原关系与已有配置，不制造路线。

**P7 实机验收补充（百分数输入，2026-11-09）**：任务问「把 0.26 写成百分之几」，用户填写百格 26 格、小数 `0.26`、百分之几 `26` 时，这是一份数学上正确的作品。检查规则必须接受「百分之二十六」中的数字 `26`，允许写作 `26%`，并兼容旧记录中的 `26/100`；不得要求孩子从未说明的分数格式猜出隐藏答案。错误反馈要指出百格、小数还是百分数表达存在问题，正确反馈应解释 `26/100 = 0.26 = 26%`，而不是笼统说「再试试」。旧错误尝试、历史检查和草稿不得因此被删除。

**可复核工程证据**：PR #41 与 [GitHub Actions 42575508211](https://github.com/runlinx-eng/math/actions/runs/42575508211)；P7 29 个 Chromium 场景状态，0 个未捕获错误，原 P4/P5、3D 连续性、P6-B 布局和完整其他浏览器回归通过，截图在 \`math-required-checks-browser-evidence\`。截图生成不代表已逐张完成人工视觉审阅，自动测试不代表儿童已独立理解。

**下一步 P7-D3/D4**：以现有公共区域分别适配并真实验收操作型、解释/论证型、跨知识联合型任务；优先修补长教具滚动/反馈可达性、总结与足迹接续、提示后的真实思维反馈；随后安排 Mac 人工及儿童独立操作。保留 Issue #34 开放直到产品体验收口。

### 10. P7 统一导航：一套操作词汇与明确去向（2026-11-09）

「探索／学习／足迹」是**唯一的全局视图切换**。切换这三个视图，只暂时收起正在使用的学习现场，不卸载原 iframe，不重置当前知识点、3D 相机、草稿或操作历史。选中知识点的单一主操作在 P11 第二轮按本知识的真实未完作品显示「开始学习」或「继续学习」；从该知识仍直接进入同一学习现场，不额外增加选择页面。无原生课程时主操作为「查看联系」，早期活动保留独立辅助入口。

**跨面板动作必须遵守以下语义**：

| 入口 | 唯一可见文案 | 实际动作 |
| --- | --- | --- |
| 选中知识点的学习操作 | **开始学习／继续学习**（依据该课程真实未完记录） | 只进入当前知识对应原生课程；已有尝试或草稿时按原记录恢复，无记录则开始；不增加试玩或中转页面 |
| 尚未开始的推荐学习 | **开始学习** | 打开推荐的真实任务，不伪称「上次未完成」 |
| 有实际保留记录的学习 | **继续上次学习** | 进入此前保存的学习现场，草稿和尝试保持 |
| 已留下的待续问题 | **回到待续问题** | 只恢复该问题已记录的知识或学习现场 |
| 学习或足迹/入口面板的明确关闭 | **返回知识空间** | 返回原 3D 空间及所选知识，清除工作面地址参数；此前学习记录不删除 |
| 任务内检查／下一题／总结 | **检查我的作品／进入下一题／整理这次发现** | 只改变当前任务进程，不作为全局导航 |

两个容易混淆的概念必须区分：**顶部视图切换是暂停**（临时收起，随后点「学习」可原样恢复未卸载的界面），**明确的「返回知识空间」是关闭本次任务面板**（重新打开时从原学习记录恢复，不清除数据）。学习任务总结后的返回也直接到原 3D 空间，不得因原 URL 带有 `surface=learn` 而跳入第二层「学习入口」。若选中知识正好就是「继续上次学习」推荐的对象，学习入口只能显示一项该知识学习操作，不重复提供两个实际指向同一任务的主按钮。

回归应覆盖：从选中节点、学习入口、足迹分别进入活动；顶部「探索→足迹→学习」反复切换时 iframe/作品/相机保持；显式关闭从不同来源都回到空间；浏览器刷新与后退；实际保存与继续不产生额外学习证据。命名规则不能由网址来源改变。

### 11. P7 需求收束：最少入口、统一交互、完整能力覆盖（2026-11-09）

**正式产品要求：用最少的必要入口和操作决策，在同一个连续的 3D 上下文学习现场，承载现有全部有价值的学习能力；精简导航不允许丢失、误藏或破坏尚未归类的内容。**

这是下一轮 P7-D3 的**设计及实施门槛**，不是「已完成全量功能清查」的结论。已有四区面板、五种派生状态和导航名称是基础，仍须对照现有真实功能逐项核对。

#### 11.1 固定交互，不强制固定数学活动

- 全局视图仅负责「探索／学习／足迹」；在当前知识只有**一个明确的学习入口**，再次打开按实际记录自动接续。明确关闭返回相同知识空间，顶部切换不丢现场，拒绝再次出现学习中心、路线中转、试玩/正式任务等重复层级。
- 同一工作区固定**当前问题 → 数学操作 → 检查及依据 → 发现与继续**的阅读主线；主行动随实际任务状态改变，不把检查、重试、下一题、拓展、返回摆成同级选择题。
- 学习过程允许观察、自由尝试、预测、操作、解释、推理、构造、反例、换条件、联结知识、重试和回看；这些是活动可使用的行为，**不要求所有任务都机械经历同样的步骤，也不能为「统一」而重写教具或判题规则**。
- 显式检查才产生提交证据；修改后的作品必须重检。结果、过程、思维线索与长期发展分开反馈，单次正确不等于掌握。

#### 11.2 先核查全量能力，再做入口减法（P7-D3 前置条件）

从**最新 main 的真实源码、活动配置、实际浏览器操作和保存记录**联合盘点，不能只看页面当前可见按钮，更不能把尚未出现在固定面板中的能力视为无用。

至少覆盖以下能力域：

| 能力域 | 必须清查的内容 | 统一工作区的建议归属 |
| --- | --- | --- |
| 当前数学问题与任务 | 知识目标、真实来源任务、条件/进度、活动参数、已有提示/示例 | 当前问题；必要说明随任务出现 |
| 直接学习与操作 | 纸带、数轴、百格、测量、模型、调查、猜想、自由操作、表达、推理、反例、错误作品 | 操作区；保留活动专属教具 |
| 检查与解释 | 输入约定、可接受的等值表达、判题、提交快照、针对性提示、数学理由、修正和重检 | 检查与反馈；原位修改 |
| 成果与思维证据 | 草稿、独立尝试、提示使用、错误历史、作品、自由文字、可能的思维方法线索 | 当下反馈与按需展开的证据；不得虚构掌握 |
| 知识关系与拓展 | 前置/后续关系、短路线、跨知识联合任务、换条件、模拟与真实实践的区别 | 发现与继续；真实关联且可主动访问 |

| **尚未归类的其他能力** | 代码/配置/旧运行器中仍存在，但暂时无法安放到上述区域的内容、原入口、记录或特殊交互 | **保留可访问入口，建立「待归类」登记；不默认删除、不悄然隐藏** |

上表是**盘点范围，不是声称已逐项完成映射**。参考存量 587 个来源节点（领域 537、思维 50）、1,223 条来源关系、已有有限任务、关联活动和历史成果；实际数量、文件位置、去重与覆盖须以最新源码清单重新核实，不把数学节点数量误当成界面功能数量。

#### 11.3 一份可追踪的「现有能力 → 交互去向」对照清单

每个真实能力/特殊活动类型至少登记：**来源路径/标识、原入口及触发条件、用户真正要做的事情、当前保存/判题依赖、统一 UI 的承载区域、状态与主操作、迁移后如何访问、代表性自动/人工验收证据、负责人/未解决问题**。

状态必须区分：**已映射且可访问／待归类但原入口保留／已映射待验证／已确认缺陷**。不能用「已折叠到更多」代替证明可找到、可操作、可接续；无法归类者列明原因、保留路径与后续决策，不得默默消失。

**删除或合并旧入口的前提**：已证明原功能有等效或更清楚的新入口，并通过关键流程、真实数据、错误/草稿、备份/离线及旧记录恢复的相关回归；必要时提供迁移映射。没有这些证据，旧入口先保留并标记，不得为了数量好看而删掉。

#### 11.4 实施顺序与验收门槛

1. **P7-D3-A 全量盘点与差距清单**：以代码和实际操作核查原入口、任务、教具、辅助行为、记录和历史兼容；先完成可复核的能力映射表，特别列出未归类项。
2. **P7-D3-B UI/状态适配**：按表逐项确定合并、原位展示、按需展开、保留独立工具或待归类；优先去掉重复决策，**不是减少学习可能性**。
3. **P7-D3-C 不同任务接入**：操作型、解释/反例/推理型、跨知识联合型各选真实代表任务，保留各自专用操作和检查依据；逐个核对「题目表达—输入格式—判题—数学反馈」一致性。
4. **P7-D4 分层验收**：Node/Chromium 检查功能可达和完整学习闭环；Mac 人工检查首屏、主操作、长内容滚动和所有保留入口；再单列儿童独立操作、数学教研和长期迁移证据。自动通过不等于教学有效。

**完成条件（不可缺一）**：新用户从当前知识直接开始 → 观察/操作/检查/解释/继续 → 返回与恢复无需理解软件层级；现有能力清单每项都有可复核去向，**待归类项数量、原入口和处理计划明确可见**，没有无故消失的功能或学习记录。全部归类不是可以删除剩余项的理由，未验证的项目不得冒充完成。

#### 11.5 按学习步骤固定框架与主按钮（P7-D3 设计合同）

固定的是**同一学习框架和主要按钮的位置**，不是强迫所有数学活动使用同一套数学操作。任何任务在当前 3D 知识位置打开时，都沿用同一个阅读顺序：**当前问题 → 专属数学操作/作品 → 检查结果 → 主要下一步 → 按需查看资料和记录**。总结阶段仍沿用这套区域，主动作位于自主发现输入之后，不能把「返回」插在「想一想」和「自己的发现」之间。运行中不可根据页面状态反复调换这四个区域的 DOM 顺序。

顶端固定三个**引导性**学习步骤，不是三个必须点击切换的模式：**① 探索与操作、② 检查与修改、③ 发现与继续**。原任务内部的观察、预测、解释、构造和反例行为始终原位进行；当前高亮由真实作品、提交和验证状态自动决定。题目进度继续使用「任务 x / n」，不以三个学习步骤替代题目数量。

| 来源真实状态 | 当前学习步骤 | 同一操作区唯一强调的主按钮 | 其他入口 |
| --- | --- | --- | --- |
| 初次进入、正在操作 | 探索与操作 | 「检查我的作品」（特殊数珠等未准备好时禁用「检查本题」） | 必要教具、按需提示 |
| 本次检查不成立 | 检查与修改 | 「修改后重新检查」；不增加“进入修改模式” | 原位作品、具体错误依据、提示、历史 |
| 作品已修改但尚未再次提交 | 检查与修改 | 「重新检查」；旧通过状态不得冒充当前结果 | 旧记录仍在，但不给当前作品成功解释 |
| 检查通过且本组还有题 | 检查与修改 | 「进入下一题」 | 再检查、必要提示按次级展示 |
| 最后一题通过 | 检查与修改 | 「整理这次发现」 | 继续使用原有检查依据，不强制打分自由解释 |
| 整理发现、无待保存文字 | 发现与继续 | 有真实路线或来源边则「继续学习/继续探索」，否则「返回知识空间」 | 自己的发现输入可选；隐藏无意义的禁用保存按钮 |
| 有未提交的发现文字 | 发现与继续 | 「保存我的发现」 | 原真实继续入口仍可访问但不争抢主按钮；草稿自动保留 |
| 保存成功后 | 发现与继续 | 回到真实继续／返回入口，紧贴输入框显示保存确认 | 已保存原话可见、历史和来源仍可查 |

**主要行动必须属于当前阶段，且同一时刻只突出一个**。统一操作栏出现在作品/发现输入之后；辅助按钮（提示、复检、重试、重新做整组、学习记录）不与主操作同级。源数学解释、来源资料、任务/思维证据仅根据当前状态和请求展现，不能提前回答孩子需要独立解释的问题。

验收必须同时检查：不同活动真实提交及修改、三个阶段标识和主按钮一致性；表达与保存/继续的顺序、保存成功与失败、草稿恢复、无真实后续时的返回；1440×900 与 1280×720 真实 iframe 内第一屏关键操作可达；原判题、不同教具、历史、旧备份与单一 3D 空间未被改坏。**Node/Chromium 技术通过不等于儿童理解或完整数学教学验收**。




#### 11.5 前台能力、按需辅助、后台能力与待归类功能（P7-D3 产品决策）

**完整能力在系统内，最少决策在用户眼前。** 四层划分是界面展示规则，不代表删减学习功能：

- **前台当前操作**：当前问题、专属教具、实时操作、实际提交检查、错误修改与唯一主行动。一个时刻只突出一个下一步；不同任务不强制相同的内部操作步骤。
- **前台按需辅助**：孩子请求的提示、已核验后适时出现的数学解释、来源关系、联合学习、换条件、拓展及自主发现。只在相关学习状态或用户主动查看时出现；不能把功能集中藏在模糊的「更多」里，必须保留可理解的入口。
- **后台与记录工具**：判断规则、提交快照、思维线索依据、保存、历史、离线、备份与兼容性逻辑默认不占题面；失败和关键保存结果必须反馈。导入导出和历史记录经「足迹／记录工具」按需可达，后台不等于不可访问。
- **待归类保留**：旧自由操作、早期工作面与独立实验、旧测验。原始资料、旧记录及当前可访问路径不删除；如果旧入口本身已不可达，显式列风险，不把它当已被取代。

**状态决定一个主动作**：首次进入直接操作、作品具备后检查；失败时指出具体怎么修改；作品改动后重检；通过后进入真实下一题；最后一题后先整理自己发现（文字可跳过）；有未提交文字时保存优先；没有草稿时，继续真实已配置关联任务，否则返回原知识空间。辅助的返回、重试、历史、其他关系可访问但不重复与主动作争抢视觉焦点。操作通过与孩子自己的解释、掌握能力是不同层次的证据。

**教学顺序**：孩子需要独立回答「为什么」时，系统不得先用完整 `lesson.summary` 回答该问题；系统数学说明保留，在孩子表达后或主动选择查看时展示，并区分当前作品的核验事实、系统解释和未经核验的自由文字。

**可追溯验收**：D3 能力映射的每一行须有前台/后台分层、出现条件、保留访问路径；由真实 Node 与 Chromium 证据验证“一个主动作、按需辅助可找到、旧能力不丢”。仅登记规则不视为运行时已实现。参见 [P7-D3 清查记录](P7-D3-CAPABILITY-AUDIT.md)。

### 12. P7 发现保存后必须有反馈与真实后续学习入口（2026-11-09）

**实际 Mac 阻断：** 完成「同一个量，换个名字」4/4 后，孩子在总结页写了「一个是十分位，一个是百分位」，点击「保存我的发现」却看不到明确确认；虽然路线 A 后面还配置了「半杯，还能怎样记」，主操作只剩「返回知识空间／重新做这组任务」。这使保存与继续学习的因果关系断裂。

**统一完成态规则：**
- 文字解释是可选证据；输入时自动保留草稿，只有明确点「保存我的发现」才写入历史 \`notes\`。保存**成功**后在同一可见位置反馈「已保存」，展示刚才的原话及「解释尚未核验」。保存失败必须显示现有存储警告，不得给假成功提示，也不能清空未保存文字。
- 若本条真实已配置的学习路线中还有**未完成的后续任务**，保存之后把「继续学习：下一处实际名称」作为唯一主动作，直接加载原有任务运行器；「返回知识空间」仍是辅助选择。若整条路线已经结束，则以「返回知识空间」为主动作，不虚构下一课。
- 尚有未归档的文字草稿时，「保存我的发现」才突出为主操作，继续或返回可以访问但不与保存争夺焦点；草稿自动保存、未提交的自由解释和历史尝试不能因为继续而丢失。完成后无需再次进入学习中心或二次点击「开始」。
- 已保存的文字在总结页可立即看到，刷新、切换任务、回到 3D 以及足迹恢复后仍可查询；不重写数学判题、来源路线或 \`math-explorer-v2\` 数据格式。一次提交正确或写下解释不自动证明掌握思维。

**回归验收：** 至少验证从 3D 嵌入式和直接运行器进入「小数」4/4 → 输入发现 → 保存一次且屏幕可见确认 → 刷新保留 → 点击继续学习「半杯，还能怎样记」→ 下一任务从原进度开始，旧记录和相机不被清空；没有真实后续任务时只出现返回空间。并验证有草稿但尚未保存、存储写入失败、旧版已有 notes 的恢复边界。自动检查与 Mac 人工操作、儿童独立理解必须分别记录。

### 13. P7 失败状态必须给出具体下一步；P9 思维节点按真实证据呈现（2026-11-09）

Mac 实际截图：学习「半杯，还能怎样记」第 1/2 题时，要求在百格上表示 1/4，但当前提交为 20 格和小数 0.2。旧界面只能显示一条泛泛的「先看整个百格」与「修改后检查」，没有在当前作品附近说明应该修正涂色还是修改小数；在检查未通过时也不会出现下一题按钮。

**固定交互**：检查不通过 → 在同一个「检查与反馈」区显示上次实际作品与具体**下一步怎么改**（如将 100 格分成 4 组，选取其中 1 组，核对小数并重新检查）；修改后告知旧结果不再适用；检查通过后恢复真正的下一题或总结入口。禁止用「返回学习」或新增学习页面代替操作指导，不直接把提示造成未经用户操作的作品。

### 15. P7 路线末端：总结可跳过，已有真实关系可直接继续（2026-11-09）

Mac 人工截图：路线 A 的最后知识「半杯，还能怎样记」两题已完成，进入「整理发现」后，只有「返回知识空间」作为主动作，另有「重新做这组任务」，而与该知识确有来源关系的联合任务被埋在折叠区。文字总结输入框仅有问题占位字，保存按钮因此不可用，但没有说明**写不写都可继续**。孩子完成了一整条路线，却需要退出并重新寻找下一处学习。

**需求与实现：**

- **路线上最后一项的完成，不是整个数学树学完。** 完成时明确「本条路线的任务已完成」，底部知识节点计数仍属于独立维度，不把它当成学习题数或思维能力等级。
- **保留当前一个学习工作区。** 先寻找该路线的实际下一知识（若存在且尚未完成）；当路线最后一项已结束时，仅从原有 `BRIDGES` 中挑选与当前知识存在真实 atlas 来源边、未完成的联合任务。优先同一路线中最近的已学前置知识，从对应联合任务直接继续，不生成“自动第五课”，不创建第二张图或新数据。
- **关联任务是可选，不是强制新关卡。** 在原完成界面将唯一一个已配置的关联任务突出为「继续探索：实际任务名」，「返回知识空间」保留为辅助操作；同一任务不再同时重复展示在总结折叠区与更多菜单中。完成此联合任务后不递归安排新的桥接练习；没有可验证来源或所有关联任务都已完成时，明确返回同一知识空间。
- **孩子先表达、下一步仍首屏可见。** 依据 P7-D3-B 的 Mac 截图复核，完成阶段的真实 DOM 与视觉顺序统一为「简短问题 → 作品检查结果 → 可选的自主表达 → 唯一下一步 → 按需查看的系统数学说明、知识联系、拓展和个人记录」。系统原结论默认收起，不在孩子独立解释之前抢答。嵌入式短视口可压缩重复通过状态卡与辅助文字，但保留顶部检查状态、专属解释问题及保存入口。浏览器要测主按钮矩形位于真实 iframe 首屏，不仅测元素存在；有未保存文字时保存是唯一强调操作，文字可跳过且不丢草稿。原来源课程说明作为记录资料按需可查，辅助栏目同时最多展开一个，不能以折叠代替可访问性验证。
- **文字发现不应挡住学习。** 文字总结可选；输入框只显示短占位提示，明确写明“不写也能继续”；空草稿时不显示无意义的禁用保存按钮，既有学习接续按钮直接可用。若写了文字，保存先突出，成功后确认并恢复接续按钮；草稿、历史、错误与已保存文字都保持在现行 `math-explorer-v2` 记录里。
- **思维方法自然延续。** 「半杯，还能怎样记」在总结中轻量提示由两题已检查作品支持的「连接不同表示方式」方法，以及可迁移问题；不把这是一个新能力考试，不因答对就归因于独立论证或已掌握 50 个思维节点。
- **验证边界**：真实浏览器从三杯水通过→总结（空文字）→立即看见一个来源可查的关联任务→可选写文字/保存→直接进入关联任务→旧记录、3D 相机及离线仍可恢复；没有原始来源边或没有未完成关联任务时不得编造后续。儿童实际体验与整体 50 节点的成长反馈仍需分开验收。

### v49 旧关系地图的组织与后续能力

以下位置规则保留供旧地图和旧现场恢复。全部 587 个节点的三维位置由来源与本地稳定分类生成一次：

- 水平位置对应五主题、23 分组，颜色对应主题；同组节点在平面上靠近。距离不创造先修关系，也不另编码跨主题连接数。
- 高度取 hard 关系图的最长前置链：无 hard 前项的节点为第 0 层，其他节点高于全部 hard 前项。851 条 hard 边共享同一规则，包括跨主题边；当前有 26 层。372 条 soft 边不参与分层。层数是来源结构，不是年级、难度、时间、掌握或必须执行的路线。
- 实线与箭头表达 hard 来源方向，虚线保留 soft 辅助关联。全景低对比显示全部关系，选中后突出真实直接联系。节点基础尺寸相同；选中、完成、未完现场和待续问题另作标记。

构造、解释与迁移也存在于传统课堂。本项目的特点是空间组织、可改变的对象、知识联系和持续记录；不把交互形式本身当作理解证据。

DI–DO七条两节点路线加入display。连同C/K共九条，三个方向各三条，孩子不用从大列表找起点。原世界与源关系不变，26条新增联合活动逐条核对源边。14个节点的42个源目标对应45个有限任务。

先逐条观察或放点，再读图中的关系。类别与连续区间不同；时间距离按实际小时摆放；分数点图保留空刻度；每个扇区单独核对份额；两组比较使用同一把尺。图画符号的单位可不是1。给定分组图不泄露原始身高，不从分组图还原确切最大值或某个单值频数。

五数图采用明确的最小最大须线和上下半组取中间的约定；改一个内部数仍可保持五个位置，形成实际反例。趋势线允许多个合理画法，但不允许任意穿过或强迫逐点连接；无明显直线趋势可不画线。模拟拉伸保持相关程度，收拢残差才更贴近直线；共同天气因素是人为设定的机制，不是现实因果证明。

已放齐的点收起录入控件，下一步仍是看图和应用。第一次错误、模拟杯子结果、半填坐标、解释原话、后来草稿与空间视角都留存。集中区间和趋势线允许合理变体。自由说明只保存不作语义评定；屏幕构造不等于纸笔作图、实物测量或真实调查。依据见[B20研究](phase5/B20/RESEARCH.md)与[逐目标覆盖](phase5/B20/COVERAGE.md)。


## B21的比较与推断

两组始终使用共同尺度；同均值可以有不同形状，同中心差/MAD比值也不唯一决定重叠。摘要需交代来历、单位与适用范围；允许匹配数值和解释侧重点的不同代表值。长尾保留真实间距，图本身不证明原因。

随机从完整名单无放回抽取，每轮记录后全部放回。样本规模分排对照；随机不保证每次样本恰好代表整体，大样本也不修复选人偏差。把观察范围当误差保证、把外推数当准确清点均不通过。原抽样编号和半填结果可作为明天的起点。

## B22的可能与不一定

chance包的旧L与DW–EC共八条路线进入三个方向。先圈有利结果、排机会、重复试验、比较袋子变化、搭路径与两圈；最后总结概率、补集、独立与依赖、并集与交集。每条路线只展开2–4个节点，路线和空间距离不是先修关系。

## P8｜实际学习现场的题目与操作顺序（2026-11-10，PR #55）

学习现场的可见顺序调整为「当前真实知识与非强制进度 → 本题完整问题与操作提示 → 原有数学教具及输入 → 唯一检查／下一步按钮 → 实际检查反馈 → 按需拓展」。顶部仅保留简洁的知识标题与学习状态；唯一行动栏位于真实教具之后，在长内容滚动时吸附在学习区底部，因此按钮不会抢在题目前面，也不会另造第二个提交入口。各题原有判题条件、帮助动作、进度记录、错误修改与总结文字不变；是否可以检查仍取决于原任务就绪条件，空答案不以 UI 文案冒充成功。

该阅读顺序必须使用同一个 `#work`、`#actions` 与 `#action-cue`，不能复制题目作为第二套操作或隐藏现有专属教具。检查顺序、首次错误、修改后重新检查、可选解释和保存失败路径仍按原记录驱动。验证由 `tests/p7-d4-multi-type-browser.cjs`、`tests/p7-learning-panel-browser.cjs`、`tests/p7-d5-entry-browser.cjs` 以及实机视口截图共同承担；当前 PR 的技术通过不等于儿童自主理解或 Mac 人工验收。
