## 数学和记录边界

`order-evidence.js` 从实际保存的原表达式字符串另建精确有理数 AST。字面数、括号、同层左结合、幂的右结合、负号和平方根分别处理，不调用 eval/Function，也不把原 Number AST、value 或 equivalent 当数学答案。原模型只用于核对既有界面行为、保存棋盘、first、steps、done 和末次 issue；每次有效归约另外用精确量和实际依赖核对。

原工具可能接受 `1/5 → 0.20000001`，也可能把 `320.00000000000000000001-125` 舍入为 195。它们保留原评分和真实尝试，在当前有效构造仍不精确时不出严格反馈。后来实际重新摆出、逐块精确完成，可以恢复证据，旧近似步骤、失败和提交不被删除。

每个历史事件保留全部 38 个根字段。适配器检查它们在上一个实际界面状态是否可见；reset 后已填写但变隐藏的 result/answer 必须保留原值，不能要求清空或允许任意改写。完成节点的按钮和没有选择时的归约按钮已经消失，不接受伪造点击。选择尚未就绪的父节点及之后的失败归约是原有可见操作，应保留失败而允许正常纠正。

已完成构造之后失败的 build 不清掉原树与步骤。恢复表达式输入后，原判题允许重新检查原作品；适配器保留该失败及末次 issue，只核对仍存在的精确构造。未点击 build 的 pending 文本独立于已摆出的 raw 字符串。它必须与原树精确结构一致才允许当前严格反馈；原 Number 认为等价、但精确数值不同的 pending 文本保持拒绝。反馈不会把输入编辑算成另一次构造。

精确计算只在原有 200 个规范化字符、2,000 个历史事件范围内工作，并限制中间有理数为 4,096 bit、整数幂绝对值不超过 64。17 道原生关系远小于该界限。旧 `0.5^1000000000` 等超出精确预算的实际接受记录仍按原行为保存，仅不赋予该旧构造精确证据；之后 reset/build 的正常精确构造不被永久否定。不增加持久 epoch，不改 State、原任务、判题、学习记录 v2 或备份语义。
