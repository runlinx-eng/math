# P7-D3-B｜学习完成页前后台能力分层与唯一主操作

> 本工作基于 Draft PR #49（真实关联继续与首屏可达性），以其 `0f8981b5d912ef1910059dff53cc17e629365027` 为开发起点；不改任务数据、3D 节点、判题、存储或旧入口。本 PR 为依赖 #49 的独立后续改动；#50 的能力清查和前后台分类另行审阅。

## 1. 观察到的缺陷

2026-11-09 用户真实 Mac 截图中的「等值分数」总结页，在孩子回答「为什么」之前已经展示 `lesson.summary` 给出的完整数学结论，同时并列出现「保存」「返回」「重新做」等操作，底部重复的记录与关系入口放大了操作负担。

问题不是数学说明错误或缺少能力，而是**答案出现时机与当前最需要操作的层级**。单次完成数值匹配是已验证的作品结果，孩子是否独立作出解释仍未经核验。

## 2. 本次实现的展示合同

| 类别 | 运行时处理 | 保留的能力 |
| --- | --- | --- |
| 当前任务｜前台 | 总结页先显示简短「你有什么发现？能说说为什么吗？」和「操作检查已通过」，以一条实际可达的关联路线/桥接活动作为主 CTA | 保持 #49 的来源校验、返回原空间、未完成路线跳过与首屏按钮 |
| 可选解释｜前台辅助 | 原 `REFLECTIONS[id]` 在输入区域作为该知识专属问题，不写可直接继续；输入草稿时「保存我的发现」成为唯一强调操作，保存/失败反馈紧贴输入 | 原 `notes/draft`、历史尝试、异常警告、旧模型恢复 |
| 系统数学说明｜前台按需 | 原 `lesson.summary` 从默认可见的总结卡移到**关闭的** `#system-explanation`；孩子主动展开才读到结论。 `quarters` 的 MP.2 线索随原数学说明按需可见 | 课程原数学内容、既有基于提交作品的检查解释和思维来源 |
| 过程证据与复习｜后台/辅助 | 总结页不重复绘制 `p3-review` 统计，完整记录仍在 `#record`；主按钮行移除重复「返回」和「重新做」，已配置的重试可在 `p3-more` 找到 | 原检查历史、每次错误、提示、重做本题、实际练习关系、应用建议 |
| 退出 | 顶部 `#back` 保持关闭学习、返回原知识空间。没有任何实际后续任务时仍以「返回知识空间」为主 CTA | 当前 3D 节点及相机状态不动 |

**说明**：这些是前台呈现与入口主次的修改，不是自动识别孩子的思维。对孩子自由文字不做数学判分。操作型、反例型和联合型在任务运行期间继续使用各自原教具及判题，不强行统一为新题型。

## 3. 验收门槛

1. 源码与 Node：`lesson.summary` 未删除，确实只放在可主动展开的数学说明中；单一总结主 CTA；历史/重试在辅助区域继续存在。
2. Chromium：真实等值分数三项任务完成后，首次呈现没有直接展示总结答案；打开 `#system-explanation` 才看到系统数学说明。保存文字以后仍能直接继续下一课并恢复记录。
3. Chromium：三杯水最后一题完成后，系统总结与 MP.2 方法线索初始关闭，用户主动查看可读取；页面只有一条真实源边关联后续主操作，且在真实 iframe 首屏可达；原 `#back` 可用，`p3-retry` 仍可找到。
4. 保留 #49 对 1440×900 内嵌首屏的 `getBoundingClientRect()` 断言、旧记录、保存错误与相机恢复断言。
5. Mac 手工验收（未完成）：分别在 1440×900、1280×720 和紧凑面板中，测试是否优先看见问题和下一步，系统解答是否默认收起，保存前后是否只一个主按钮，能否找到历史重试/拓展；请孩子独立解释前不点系统说明。
