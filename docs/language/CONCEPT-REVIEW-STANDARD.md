# 知识点内容审查标准

状态：2026-11-02，工作分支草案；合并主线后才成为正式内容规范。适用于 537 个知识地图节点的解释内容，不适用于另外 50 个数学思维节点。

## 一、目标与边界

目标不是把每个知识点写成同一种七段式文案，而是确保孩子看到的解释**准确指向一个真实数学目标，并能帮助其辨认、解释或操作这个目标**。

概念解释是知识详情中的辅助理解层，不替代完整学习活动、来源材料或教师教学，也不单独证明孩子已经掌握。打开解释、看图、读例子或完成一次提示，都不能自动成为掌握记录或学习完成证据。

不可改变：来源节点 ID、来源名称、数学关系、关系方向与强度、空间坐标、学习路线、活动完成条件和学习记录。解释只解释已有内容，不创造知识依赖。

## 二、每个节点先核对来源

写解释前，必须按来源 ID 核对 `dist/data/math.json` 中的：

- `title/name`：当前知识点指向什么；展示名称与正式数学概念可以不同，但必须能追溯。
- `description`：本节点实际要教什么，作为范围核对的主要依据。
- `evidence`：孩子需要表现出的可观察行为；解释和练习不能只覆盖容易写的部分。
- `assessmentPrompt`：来源预期如何判断目标是否达到；可改写情境，不得改变目标。
- `ageRangeStart/ageRangeEnd`：语言、数值、符号和先备经验的适龄参考，不是硬性年级分班。
- `type/domainId/lesson/hasResearch`：帮助选择解释方式、领域和现有内容依据。
- 真实前置关系：用于理解背景和边界，不允许从相邻名称推导不存在的依赖。

**研究缺口规则：**若 `hasResearch=false`，现有 description、evidence 和 assessmentPrompt 只能支持来源目标的初步理解，不能当作完整教研资料。必须标记“待补研究/独立数学复核”，不得为了填满解释字段而猜补课程范围。

一个节点可以有多个子目标。审查时必须写清本解释覆盖了哪些核心内容、哪些由现有学习活动承接、哪些仍缺资料。不能用一条漂亮定义暗示整个节点的学习目标都已覆盖。

## 三、解释字段的职责

| 字段 | 必须回答 | 不合格表现 |
| --- | --- | --- |
| `formal` | 这个内容的准确数学概念叫什么？ | 只写口号、活动标题或模糊比喻 |
| `definition` | 它是什么；成立需要什么条件、范围或单位？ | 只描述操作表面；遗漏关键条件；把局部例子当普遍规律 |
| `simpler` | 换一种更容易理解的说法，是否仍与定义完全同义？ | 为了通俗而改变数学含义；省掉会导致错误的条件 |
| `example` | 一个具体情境怎样体现定义，计算或表示是否正确？ | 只有答案没有过程；单位、数值、图形或前提不一致 |
| `counterexample` | 哪种相似情形不成立，错在什么地方？ | 只说“不是这样”，却不解释边界；反例本身也不满足条件 |
| `tryIt` | 孩子能否独立做一个相近但不照抄的任务？ | 只是重复阅读定义或照抄例题；没有可观察的操作/解释 |
| `why` | 为什么这个关系、步骤或判断成立？ | 重复定义、空泛鼓励，或用结论解释结论 |
| `visual`（可选） | 图像是否比文字更清楚地表达数学关系？ | 为了统一而硬加图；图中数量、比例、方向、单位或标签不准确 |

七个文字字段是内容槽位，不是固定篇幅。某字段可以短，但不能空泛；图示是可选项，不要求 537 个节点都配图。

## 四、按来源类型调整审查重点

来源 `type` 是内容分类，不是必须照搬的教学模板。

| 来源类型 | 必须重点解释 | 特别检查 |
| --- | --- | --- |
| `CONCEPTUAL` 概念型 | 对象/数量/关系是什么，关键属性与适用条件 | 是否把一个例子误当成定义；是否区分相近概念 |
| `PROCEDURAL` 操作型 | 何时使用、关键步骤、步骤为何有效、怎样检查结果 | 单位、数位、进位、运算顺序、适用条件和结果核验 |
| `REPRESENTATIONAL` 表示型 | 图形、符号、表格或坐标中的元素分别代表什么 | 比例、刻度、轴、方向、单位、图与数学对象的对应，以及图示不能表达什么 |
| `LANGUAGE` 语言型 | 术语/符号怎样读、表示什么、与近似术语有何区别 | 不只教名称；必须解释符号在关系中的作用 |
| `META` 策略型 | 怎样提出问题、选择策略、监控过程、检查结果与限制结论 | 不把策略说成唯一算法；说明证据能支持多大范围的结论 |

## 五、统一质量门槛

每个样板按以下维度分别记录，不合并成一个含糊的“通过”：

1. **来源对齐**：ID 正确；定义、例子和练习对应来源 description/evidence；没有擅自增加目标。
2. **数学正确**：公式、推理、图形、数值、单位、边界条件和反例都成立；必要时明确分母非零、等可能、垂直高、区间边界等前提。
3. **范围完整**：覆盖该解释承诺的核心目标；若只覆盖子目标，明确写出未覆盖部分及承接位置。
4. **表达清楚**：正式定义准确；通俗说法不失真；例子和反例能区分关键边界。
5. **可操作验证**：`tryIt` 能让孩子做、说、画、比较或检查，并能观察到与目标对应的行为。
6. **适龄**：依据来源年龄范围检查词汇、数字大小、符号、先备知识和任务复杂度；不能仅靠缩短句子判断适龄。
7. **图示质量**：仅在图示有价值时制作；检查比例、标记、文字、颜色语义、可读性和辅助文本。静态 SVG 不得描述成可拖动练习。

### 状态用语

- **来源核对**：已核对 / 待补研究。
- **内容范围**：完整 / 部分覆盖 / 待确认。
- **数学审查**：编辑初核 / 待独立数学复核 / 已独立复核 / 发现错误。
- **儿童理解**：未测试 / 观察中 / 已按任务验证。
- **界面与图示**：未检查 / 自动检查 / 人工检查 / 不适用。

这些状态互相独立。来源核对、自动测试或编辑初核通过，不得写成独立数学审查通过；页面显示正常，不得写成孩子理解；儿童能完成一次活动，也不自动证明长期掌握或迁移。

## 六、何时可以扩展到其他节点

39 个样板校准后，允许把本标准用于其余知识地图节点的**分批起草**，但每个新节点仍需单独核对来源，不得批量套话。

扩展顺序应同时考虑：
- 来源研究是否充足；`hasResearch=false` 的节点先补研究或明确阻塞。
- 五类来源类型和 11 个数学领域的代表性，避免只挑容易写的节点。
- 年龄范围、关键前置和真实学习活动是否能支持解释。
- 当前覆盖空白和数学风险，而不是按节点 ID 或批次机械生成。

每批先抽取少量不同类型节点，按本标准审查并检查页面，再扩大批量。若同一类错误反复出现，先修正标准或生成规则，再继续下一批。

## 七、首轮校准的完成条件

- 39 个现有样板逐一对照来源 ID、description、evidence、assessmentPrompt 与年龄范围。
- 结构字段完整不再被当作内容合格；明确记录内容范围不足和研究缺口。
- 修正已识别的数学表达歧义、范围遗漏和不适龄表达。
- 自动测试只守住来源绑定、字段完整和已确认的关键数学边界；不让测试替代专业审查。
- 独立数学复核、真实页面人工检查和儿童理解测试仍单独保留，未完成不得标记为通过。
