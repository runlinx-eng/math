# 数学树：概念与文字表达基准（第一阶段）

状态：**概念层级、5 个主题与 23 个知识群、587 节点命名首轮审查已完成；关系方向和学习入口用词进入回归验收。** 2026-11-02，工作分支 `feat/language-concept-audit-v1`。详见 [主题与知识群](THEME-GROUP-REVIEW.md)、[587 节点台账](NODE-NAME-AUDIT.json)、[关系与活动反馈](RELATIONS-ACTIVITIES-REVIEW.md)。

## 核心原则

**精准命名，按需解释，多种理解路径，凭行为证据判断理解。**

- 稳定名称负责指向同一数学概念；孩子看不懂时，解释可换说法、换图示、举例、对比反例或动手试，不用模糊的别名取代数学术语。
- 每条界面文字分清「这是什么」「为什么有关」「现在能做什么」「实际做到了什么」；避免一行文字同时承担四个职责。
- 数学关系必须来自来源边；文字只能解释关系，不能创造关系、强加主干或规定唯一课程路线。
- 「浏览/看过/开始/提交/完成活动/理解/掌握」是不同事实。引导步骤完成不等于学会数学，任务进度不等于知识掌握度。
- 五大主题、23 个知识群是**组织与导航分类**；不是因名称相似而新增的数学前置关系。保留 537 个领域知识点在地图中的原位置、另有 50 个数学思维节点在学习与关系内容中可访问，不强行绘制到地图。
- `main` 交互基准 [INTERACTION-RULES.md](../spatial-learning/INTERACTION-RULES.md) 继续有效；本阶段只修改文字和相关断言，不能更改节点、关系、坐标、相机、点击权限和学习完成逻辑。

| 一级 | 主题 | 五个数学主题分类 | 一个方向、章节 |

## 第三层：内容与解释分工（14 个节点完成样板，继续扩展）

一个知识点可组织为「**正式数学名称** + **一句精准定义**」，其后按需提供：
1. 换个说法：尽量平实但保留概念边界；
2. 换一种表示：图形、数轴、表格或空间示意；
3. 举例与反例：区分成立条件、例外、易混概念；
4. 动手试试：真实可执行的观察和操作；
5. 为什么：来源关系和数学依据。

这些是**可选的理解方式**，不是要求全部堆在一张卡片。内容若尚未审稿或活动尚未实现，不应伪称解释或学习效果已经提供。

## 解释策略按知识内容类型适配

来源数据在 537 个知识地图节点中包含五种内容类型。它们是选择解释方式的依据，不是新增数学分类，也不能替代具体知识点的逐项审查。

| 来源类型 | 解释重点 | 优先使用的方式 | 容易出现的错误 |
| --- | --- | --- | --- |
| `CONCEPTUAL` 概念型 | 说明概念表示什么、成立条件和边界 | 精确定义、模型、正反例、为什么 | 只给口号或例子，不说明概念条件 |
| `PROCEDURAL` 操作型 | 说明何时用、怎么做、如何检查结果 | 步骤、单位/条件选择、结果核验、动手 | 只说定义，不告诉孩子如何正确执行 |
| `REPRESENTATIONAL` 表示型 | 说明图形、符号、表格与数学关系如何对应 | 图示、数值表、坐标点、符号与图像互译 | 只给图而不解释图上元素代表什么 |
| `LANGUAGE` 语言型 | 说明术语和符号怎样读、各部分表示什么 | 术语解释、读写示例、易混符号对照 | 只教名称，不解释数学含义 |
| `META` 策略型 | 说明如何选择方法、估算、检查结果或组织调查 | 策略选择、判断流程、验证步骤、数据调查计划 | 只教一个步骤，不说明何时适用、如何检查和结论边界 |

统一的字段只是内容容器，不是要求每个知识点机械填满相同长度。对某个节点，应优先选择最能揭示其数学含义的方式；例如直线图像需要“公式—数值对—坐标点”的对应，分数记法需要“分子/分母—等份整体”的对应。图示只有在确实准确表达关系、并能在界面中完整呈现时才加入。

**当前覆盖状态**：16 个节点已经覆盖上述五种来源类型，但每种类型仍只有少量样本。另有 50 个数学思维节点不属于 537 个知识地图节点；按既定定位，应在学习活动中根据行为证据反馈，不套用知识点解释模板。这证明模板能容纳不同内容，不代表已完成全量推广，也不代表所有解释方式已被儿童验证。
