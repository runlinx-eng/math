# 数学探索：阶段任务与验证

2026-10-24。依据当前 v6 实现和用户已明确的需求制定。本次交付是计划；下面的待办不表示已经实现或通过孩子试用。

## 完成目标

孩子在电脑上的连续三维空间中，先看全貌，再从少量选择开始学习。
每天点亮几个知识点，实际用到它们之间的联系；出现新问题时留下，
下次打开从这个问题继续。界面只显示完成／未完成，整体和任务进度简洁。

分两次形成可验收成果：

- **阶段 1–4：可连续使用的第一版。** 一条完整路线支持点亮、连通、留问题和隔天继续，并经过实际试用。
- **阶段 5–6：扩展到更多数学内容。** 验证适合三维的学习活动，再逐包扩展路线。全部 23 个分组有多少可用内容，按实登记，不把地图存在当成课程完成。

只做数学、电脑端、本地使用。不以年级和教材锁定路径，不增加家长入口。
保持五个主题和少量入口、通俗理解后逐步连接正式表达、可自由跳转的建议路线。
详细记录留在背后；每个知识点采用什么具体表现形式，在制作该活动时再设计。

## 阶段 1：走通一条完整学习路线

**状态：部分完成，下一执行阶段。**

任务：

- [ ] 补齐 A–03，使 A–01 → A–02 → A–03 都有明确问题、可做的操作、反馈和简短总结。
- [ ] 准备至少两次使用的内容：前一次认识一半与等值，后一次可从“半杯还能怎样记？”继续。下一次入口要有可学内容，不能只回到一条问题记录。
- [ ] 每项明确关键操作与完成条件；避免只打开、随便拖动或跳到总结就计完成。可借助提示完成，记录中保留实际过程。
- [ ] 每项至少有一次换条件、换表示或自己构造的机会，观察孩子能否用刚学的想法；正式名称与所做的事情对应。
- [ ] 统一开始、继续下一项、回到全景的入口与命名；保留自由跳转，默认一个主要操作现场。
- [ ] 新旧活动在同一节点下保持进度一致，原有记录不被清除；未制作内容继续明确其范围。

验证：

1. 在电脑上从全景出发，进入路线 A，完成三个任务，能继续、返回和恢复；没有按钮无去处或只能停在预览的断点。
2. 对每项分别检查未操作、关键操作未成立、提示后修正、实际完成、刷新后继续。进度与实际记录一致，重做不会重复增加总进度。
3. 检查更换整体、份数或表示后，数学关系仍成立；反馈能说明当前现象。该项证明活动规则正确，孩子是否理解留到阶段 4 观察。

交付：完整路线 A，以及对应桌面操作记录和必要截图。

## 阶段 2：点亮知识，打通联系

**状态：节点进度已有，个人连接记录待实现。依赖阶段 1。**

任务：

- [ ] 将任务完成清楚地表现为知识点点亮，保留未完成区域和整体进度；不增加新的学习状态名称。
- [ ] 为路线 A 的两条真实来源关系分别安排一个用到两端想法的小操作或应用，将完成记录对应到这条联系。
- [ ] 完成连接任务后点亮相应连线；靠近时能看见连接理由，退回全景能认出自己连起的区域。
- [ ] 默认强调当前路线和个人进展，避免重新铺满全图箭头；所有原始关系仍可按需查看。

验证：

1. 仅点开两个节点或看过箭头，不产生打通记录；完成连接任务后只点亮对应联系。
2. 两个端点分别完成但尚未做连接任务时，连线不自动完成；修正后完成可留下连接记录，首次尝试保留。
3. 刷新、重启、重复操作和备份合并后，节点与连线保持一致、不重复计数，位置不跳动。
4. 全景总数只包含已开放学习节点。A–03 与旧的小数活动是不同源节点，不能混作一个或沿用固定总数 3。

交付：能看到个人点亮区域和连接的路线 A。点亮表达这次学习任务的完成，不自动宣布永久掌握。

## 阶段 3：今天的问题，成为明天的起点

**状态：未实现。依赖阶段 2。**

任务：

- [ ] 在学习现场提供一个简短的“留到下次”入口，保留孩子的问题原话及它所在的知识位置。
- [ ] 再次打开时，优先给出最近留下的问题；一步回到相关现场，也可以主动选择别的方向。
- [ ] 没有留下新问题时，接着未完成任务或建议路线继续；不强迫每天提问。
- [ ] 今天的新增点亮和连接可简单回看，累计全景仍保留。不增加固定每日数量、打卡惩罚或额外仪表盘。
- [ ] 问题无法匹配现有节点时仍可保存，不编造关系或冒充已有课程；新问题、连接和现场一起进入备份。

验证：

1. 留下“半杯还能怎样记？”并跨日打开，能找到原话、原位置并进入已准备的 A–03 内容。另用“1/3 可以写成小数吗？”检查尚无对应活动的问题仍被完整保存，不冒充已具备解答课程。
2. 同日重开、隔天重开、未留问题、多个问题、暂时跳过、未匹配节点的问题，都有可继续的入口。
3. 当天记录跨日后归属正确，累计完成不归零；重复打开不重复增加点亮或连接。
4. 导出到独立测试浏览器后，问题、连接、学习现场和已有记录均能恢复；离线能继续已提供的学习内容。

交付：完整的“点亮 → 连通 → 留问题 → 下次继续”过程。这里的隔天继续是产品功能，不是自动提醒或后台替孩子学习。

## 阶段 4：孩子实际试用并修正

**状态：未开始。依赖阶段 1–3；由孩子实际使用后验证。**

任务：

- [ ] 至少观察两次使用，其中一次发生在第二天；首次从全景开始，第二次从上次的问题或任务继续。
- [ ] 记录孩子停在哪里、需要什么帮助、是否能说出下一步；优先修改名称、操作和反馈。
- [ ] 在活动中换一个情境或条件，看孩子能否继续运用，并用自己的话或作品表达联系。
- [ ] 询问孩子是否想继续以及具体原因，记录真实回答；不强求产生新问题。

验证：

- **使用能否继续：** 修正后，孩子可以自行进入、操作、返回全景、找到上次入口，不需要成人逐步报按钮。
- **理解能否迁移：** 在至少一个不同于原示范的情境中，观察其做法和解释；记清是否需要提示。若仍卡住，就修订对应活动，不能用“已完成”掩盖。
- **日常体验是否成立：** 孩子知道今天完成了什么、下次从哪里开始；有新问题时能留下，没有新问题时也能继续。

交付：简短试用记录、实际修正和仍未解决的问题。程序测试只能证明功能运行，不能代替此阶段，也不能替用户确认最终体验。

## 阶段 5：验证适合三维的学习活动

**状态：待设计。主流程稳定后开展，具体表现方式届时确定。**

任务：

- [ ] 从已有数学内容中选一个适合空间操作的问题，设计一项通过观察或操作发现关系的活动。
- [ ] 保持与知识地图的连续空间体验、简单操作和既有学习记录相接。
- [ ] 先做一个可完整体验的实例，根据实际使用再决定是否扩展同类形式。

验证：操作改变的数学对象或观察角度与学习问题直接相关，数学反馈正确；孩子能用操作前后的变化说明一个发现。记录空间操作带来的帮助和困扰，不能仅以“能旋转、画面好看”判定学习活动有效。

交付：一个经过实际试用的空间学习活动；不要求所有知识采用三维表现。

## 阶段 6：逐包扩展为持续学习内容

**状态：持续扩展，先做小批次。扩展前已有路线的使用问题应得到处理。**

任务：

- [ ] 先补两条新路线，使可用路线达到三条，至少涉及两个主题；每条以 3–5 个相连的核心学习节点为初始规模，具体选题按关系和孩子的问题确定。
- [ ] 每条路线都有通俗问题、动手与应用、必要总结、明确连接、点亮和下次继续的入口。
- [ ] 将新增课程与源节点、定义和关系逐项对应；新增教学编排明确为本地设计。
- [ ] 按 23 个分组逐包维护内容覆盖：已可学习、仅有资料、尚未制作分别如实登记。每批复用前述验证，不用批量生成代替数学核对。

验证：每条路线都能实际走完；每批抽查跨情境应用和使用卡点；全景进度仅随新增可用内容更新，旧完成、连接和问题保持。三个知识点点亮不能扩算成一个包含几十个节点的分组全部完成。

交付：首批三条可用路线及覆盖清单，随后逐批扩大。首批通过不等于全部数学内容完成，也不等于 587 个节点都有完整课程。

## 执行与验证方式

每阶段记录交付范围、实际验证结果和剩余问题，链接到具体页面或证据。
普通实现、修复和相应复测在同阶段持续进行，不增加逐步确认流程。

- **功能验证：** 助手完成电脑端真实操作、受影响的数学规则与记录检查；涉及进度和保存时验证旧记录兼容。使用独立测试记录，不改写孩子日常记录。
- **学习体验验证：** 阶段 4 及后续新活动需要孩子实际使用。没有发生的试用标为未验证，不用自动测试代替。
- **技术证据：** 新结果记入 `docs/VALIDATION.md`；设计变化写入 `docs/LEARNING-DESIGN.md`。不重复进行无关或已经充分通过的检查。
