## 三条跨阶段产品原则

1. **3D 知识树负责“学什么”**：呈现基础、分支、汇合、后续与真实理由；**知识有层级，操作不分层，单一 3D 空间与学习上下文连续**。
2. **学习过程负责“怎么想”**：让孩子亲自操作、尝试、解释、找规律、推理、建模与验证，而不是把学习变成答题和跳页面。
3. **学习反馈负责“思维如何成长”**：依据真实证据描述这次用了什么方法、下一步怎样反思与迁移；50 个思维节点和八条发展链保留底层结构，**不要求全部固定为 3D 球体，不能由一次答对推断掌握思维**。

## 开发、验收和收口方式

1. **每阶段以最新 main 为起点**，先真实复现问题，再明确最小设计与不可变项，然后按任务独立 PR 实施；不重新拆成多张 3D 图，不用网页级的层层进入退出代替连续空间操作。
2. **代码与学习记录边界不变**：保留 537 个领域知识节点、50 个思维节点、1,223 条来源关系、固定 3D 坐标、课程判题语义、旧草稿与作品、离线/导入导出和恢复语义；新增思维能力反馈不替代原证据。
3. **验证分层**：技术检查及 Chromium 真实操作证明实现和回归；用户 Mac 人工体验证明入口可用性；独立数学审阅证明内容可靠性；真实儿童试用和迁移表现才能支持教学有效性判断。
4. **先合并、再持续完善**：得到授权且最新 CI/必要兼容性检查通过即可合并 `main`，未完成的人工视觉、交互和教学验收在 Issue 中明确保留；合并不触发 VPS 自动发布。
5. **当前起手任务：P9 / Issue #22**。基于已有 P7/P8 学习现场与真实记录核对思维节点—任务—可观察行为—反馈；Issue #34/#30 的未完成交互体验仍需在真实复现后优先做必要修复。P10 专项验证本地完整离线、异常网络及旧记录兼容，P11 继续视觉完善；桌面安装版由 Issue #63 另行安排。

## 完成目标与范围

孩子在电脑上的连续三维空间里，可以浏览密集全图，也可从主题或短路线进入学习，每天点亮几个知识点、打通联系，出现新问题时留下，下一次从问题继续。界面保持完成／未完成与简洁进度。只做数学、电脑端、本地使用，不按年级和教材锁定路线，不做家长入口。

建设范围是本次固定来源的 **587 个数学节点和 1,223 条数学关系**。全量完成指这些节点都有实际可学习的任务及对应覆盖说明；不表示覆盖数学的全部知识，也不表示孩子已经掌握它们。一个活动可以覆盖多个节点，但每个节点必须有对应的学习目标、关键操作和验证内容。

阶段 2 和阶段 4 的 **12 个、50 个不同节点**是本次安排的制作规模，包含起始时已有的 3 个，不是独立课程数量。阶段 1 已确定具体名单与归并方式，见 [全量内容制作清单](CONTENT-INVENTORY.md)。阶段 2 实测后可调整归并和批次大小，保持全量去向完整。
