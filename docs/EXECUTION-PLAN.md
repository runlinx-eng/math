> **性质：产品决策与后续执行计划，不代表本条已经编码、测试或合并。** 本节为截至 2026-11-12 最新的 P11 后续方向；下方大量 P10/P11 过程记录及早期优先级为历史，冲突时以现行工作流、本次已明确的用户产品决策和实际源码/CI 为准。P11 第一、二轮已合并；第三轮 [PR #77](https://github.com/runlinx-eng/math/pull/77) 仍为 Draft，须单独修复其真实失败并验收，不把本规划混入 #77 或独立的 P9 [#66](https://github.com/runlinx-eng/math/pull/66)、长期规划 [#73](https://github.com/runlinx-eng/math/pull/73)。

### 目标与不变边界

- **降低使用软件的学习成本**：用户在探索、理解、学习、回顾中，看到/试一下就知道当前知识、当前操作及下一步；不新增首次使用/首次选中教程或机械弹窗。界面信息以用户情境、目的与真实学习流程组织，不以减少文字、按钮或信息量本身为目标。学习流程引导与数学理解引导分别处理，按当前任务需要显示。
- **悬停与选中清晰分工**：悬停要明显、易辨，预览节点名称和真实关联；点击即选中并展示该知识的探索信息，**不自动进入学习**；已选中对象有稳定的独立标记。悬停不能出现操作按钮群、强制变更课程或覆盖已选中详情。**没有用户要求“弱化悬停为虚线和淡色”**；PR #77 中相关视觉实现先核对正式需求和旧测试，再纠正不合理样式，不能单为 CI 绿灯削弱有效断言。
- **关系线必须让人看懂“连到谁”**：此前因标签密集而隐藏名称，如今只剩连接匿名圆点，信息价值不足。优先检查已有名称显示/避让能力，再通过透明度、色彩、线条、节点标记、标签优先级、聚焦与悬停联动恢复关联节点的可辨名称；主节点与直接关联优先，次要关系可降权，不无条件把全部 587 个标签常驻打开。知识名称、前置/后续方向和理由只能来自既有真实来源关系，不能根据 3D 距离推断。用户提供的真实视图在实施时作前后对照，验证单屏可读性而非只看截图像素。
- **学习 A 时探索 B**：课程 A 仍是唯一当前学习任务，保持 iframe/作品/草稿/进度；在 3D 中悬停或点击 B，只更新 B 的探索预览/知识详情，不自动切换到 B 的题目或清除 A。UI 要区分“当前学习对象 A”与“正在查看的知识 B”，不可冒充两个同时进行的课程；想改学 B 须有明确的用户学习操作和对 A 的安全暂停/退出路径。原有“学习模式实点 B 立刻切换课程”的测试与产品新决策冲突，实施时依据新规则同步更新交互测试，同时保留真实 WebGL 点击、命中和记录安全断言。
- **足迹保持现状**：顶部“足迹”独立工作区**继续保留**，不隐藏、不移除。原学习历史、单节点记录、准确接续、备份导入导出、离线/旧数据恢复均完整保留；是否未来整合到节点详情/“更多”，只作可讨论方案，未授权实施。不是新建后台服务器。
- **本轮不重复设计既有镜头控制**：缩放、移动和旋转已有能力继续保持；不把它们列作新增优化范围。严禁为此改动 587 个源节点（537 领域＋50 思维）、1,223 条关系、既有 3D 坐标、判题/内容语义、P10 存储 schema、Service Worker 或真实用户记录。P9 #66 与规划 #73 独立；无单独授权不操作 VPS。

### 节点学习状态：四类，按既有有效证据派生

**仅查看、悬停、选中、打开知识说明不产生“接触过”状态，也不算开始学习。** 以已有提交记录、题目清单与既有完成判定为权威，不另建一份“点亮真相”。以下是产品语义，具体分类映射需先审计真实课程配置，不得擅自修改题目通关标准。

| 节点状态 | 判定逻辑 | 地图表现 |
| --- | --- | --- |
| **未学习** | 节点内尚无按现有作答/检查流程持久化的有效题目作答记录；纯访问、自由拖动或仅存草稿不算作答 | 未学习的中性视觉状态 |
| **学习中** | 已有至少一题**有效作答记录**（包括不正确但确实提交并保存的尝试），但未完成全部“可进入下一步所需的核心题” | 与未学习区分的进行中标记 |
| **核心题目完成** | 该知识点所有**完成后才满足下一步条件的核心题**均按既有通过条件完成；还有不影响下一步的可选题未完成 | 已完成核心部分、仍可继续扩展的标记 |
| **完成所有题目** | 该节点核心题与所有可选题均已按原本完成条件完成 | 完整完成标记，与“学科能力已掌握”严格区分 |

- 核心题是“必须满足才能继续下一步”的题；可选题“不阻塞进入下一步”，但计入“完成所有题目”。不得把可选题完成设置成课程前进条件，也不得因为答错一次就标记成完成。
- 若该节点没有可选题，核心题全部完成即可进入“完成所有题目”最高状态；四种状态依实际证据互斥显示，先判全部完成、再判核心完成、再判已有有效作答、最后未学习。
- **先核实原任务模型是否真正标记核心/可选及不同活动入口的对应关系**。如尚无可靠分类映射，先产出逐节点题目分类/可继续依据的待确认清单，不根据索引、标题或题数自动分配，也不改原任务语义凑出四态。旧草稿、桥接任务、历史课程、部分完成记录必须兼容；如需改变数据格式、判题规则或存储迁移，应另行风险评审及用户授权。
- 状态只反映保存的作答与完成证据，**不推断掌握程度、独立数学能力或儿童教学效果**。地图的“当前选中/正在查看/正在学习 A”交互标记与四种长期进度状态彼此区分，不能用同一颜色混淆。

### 尚未配置课程／无法进入学习的节点：先实查，再列清单

## 三条跨阶段产品原则

1. **3D 知识树负责“学什么”**：呈现基础、分支、汇合、后续与真实理由；**知识有层级，操作不分层，单一 3D 空间与学习上下文连续**。
2. **学习过程负责“怎么想”**：让孩子亲自操作、尝试、解释、找规律、推理、建模与验证，而不是把学习变成答题和跳页面。
3. **学习反馈负责“思维如何成长”**：依据真实证据描述这次用了什么方法、下一步怎样反思与迁移；50 个思维节点和八条发展链保留底层结构，**不要求全部固定为 3D 球体，不能由一次答对推断掌握思维**。

## 开发、验收和收口方式

1. **每阶段以最新 main 为起点**，先真实复现问题，再明确最小设计与不可变项，然后按任务独立 PR 实施；不重新拆成多张 3D 图，不用网页级的层层进入退出代替连续空间操作。
2. **代码与学习记录边界不变**：保留 537 个领域知识节点、50 个思维节点、1,223 条来源关系、固定 3D 坐标、课程判题语义、旧草稿与作品、离线/导入导出和恢复语义；新增思维能力反馈不替代原证据。
3. **验证分层**：技术检查及 Chromium 真实操作证明实现和回归；用户 Mac 人工体验证明入口可用性；独立数学审阅证明内容可靠性；真实儿童试用和迁移表现才能支持教学有效性判断。
4. **先合并、再持续完善**：得到授权且最新 CI/必要兼容性检查通过即可合并 `main`，未完成的人工视觉、交互和教学验收在 Issue 中明确保留；合并不触发 VPS 自动发布。
5. **当前起手任务：P9 / Issue #22**。基于已有 P7/P8 学习现场与真实记录核对思维节点—任务—可观察行为—反馈；Issue #34/#30 的未完成交互体验仍需在真实复现后优先做必要修复。P10 专项验证本地完整离线、异常网络及旧记录兼容，P11 继续视觉完善；桌面安装版由 Issue #63 另行安排。
