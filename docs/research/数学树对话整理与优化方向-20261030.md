## 从讨论中保留下来的方向

### 1. 关系和空间应帮助理解，而不是仅提供造型

S1、S7 中用户的核心要求是：整体趋势、节点位置和形态应尽可能承载可解释的信息；看得见起点、分支和发展，同时要检查是否丢失关系、是否人为加入含义。用户用真实树的功能性作类比，是要求**框架和细节各有作用**，不是要求数学图必须长成一棵树。

S1 的实验讨论指出，单一树形可能让多基础汇合消失、把样本边界误看成真正终点；粗线、树干、角度等也可能引入来源本身没有的含义。对话所提出的“先完整结构，再按需要过滤显示”是探索方向；过滤不能删除底层关系，也不应把临时隐藏误认为不存在。

**本地对照：** 当前 v52 界面使用 v49 固定坐标：横向按五主题和 23 分组组织，高度按全图 hard 边最长链分层；全部 587 节点和 1,223 条源边可访问。节点间距离、枝干外形和路径编号不表示数学先修、难度或重要性。视角与选择改变相机或强调，不重排节点。当前设计的可解释性和孩子是否能从整体看出有价值的结构仍需实际检验，不能把横向聚集说成自动发现的知识主干。

### 2. 探索的基本单位是节点之间的真实联系

S5 将优化的重点表述为：选中节点后直接看见基础与后续，理解为什么相连，沿邻居继续探索，并能进入活动及回到上下文。S6 的具体问题补充了儿童实际会遇到的困惑：同名球如何区分、箭头是什么意思、悬停和点击有什么区别。原方案希望保留原坐标、旧现场与路线，不把箭头当作强制学习次序。

**本地对照：** v51 已实现直接联系、前后关键关系追溯、同名限定、鼠标／键盘临时预览、选择和返回，以及 1,223 条绑定源理由的中文说明；v52 默认左拖旋转，保留平移方式。代码中直接关系列表区分关键／辅助联系、展示本地说明与来源原文；追溯只走 hard 关系。具体技术记录见 [VALIDATION](../VALIDATION.md)。这说明**相应功能已经实现并有技术检查**，不等于解释准确性、首次使用可发现性或孩子能理解关系已经得到验收。中文说明尚未经独立数学审阅。

### 3. 数学思维首先作为学习过程的设计线索

S3 中用户提出思维是否主要体现在点进知识后的学习过程，而不是与空间强行绑定；S2 将实际解释、操作和解题过程作为反馈依据。可用等值分数作后续探索样例：孩子如何通过操作、对比、说明和修正观察关系。一次正确答案或一次受提示操作只能说明这次有限表现，不能单独证明思维能力已经形成或发展。

现有活动保留首次尝试、错误、提示和修正，自由解释与可自动检查的构造证据分开。**可进一步研究**如何让孩子回看自己做了什么、为什么改变想法，并跨不同活动观察相似方法；是否需要八类标签、怎样可靠反馈，以及源节点与八类思维的映射，均未确定。不能根据名称自动给活动或孩子贴能力标签。

### 4. 3D 与 2D 的价值应通过同一任务比较

S4 先提出 2D 也可表达关系，随后在用户指出空间结构价值后调整判断：3D 整体有潜力，2D 局部联系更易读，但没有证据证明 3D 优于 2D。对话里的 2D 原型在局部重排节点，因此与用户希望持续理解同一张空间关系的目标存在张力；本地 v48 也因全图和局部分别重排而被替代。

可研究一个**不改变世界坐标的局部关系读法**，例如利用现有侧栏和相机视图先验证关系能否看清；若另做二维实验，应明确它是否只是关系说明而非重新定义原世界，并保留源 ID、边、返回位置。它是待比较的设计方案，不是现在应替换 3D 的决定。比较时应使用同一批真实节点、关系和任务，而不是比较不同数据或仅比较截图美观。

### 5. 区分外部地图与学习效果

S2 用户提出知识细节可能遗忘，而结构或“代理坐标”可能成为线索，随后追问这种说法是否牵强。回复承认：地图可以保存外部位置和关系，但不能由此断言孩子自动形成内部认知结构，更不能断言相关场景会自然唤醒遗忘知识。重新找到知识、解释关系、在新情境中使用或更快重学，都是可以研究的不同结果，不是空间坐标的已证实效果。

## 需要保留的冲突与未定问题

1. **587 与 537＋50 的口径：** S3 一处同时称“587 个知识节点”和“50 个思维节点”；S2 后来改称 587 包含 537 个领域节点和 50 个思维节点。本次核对 `dist/data/atlas.json`：`domainId: thinking` 为 50，其他领域为 537；这验证了本地分类口径，不等于确认它们各自都适合作为独立能力标签。
2. **思维节点是否退出地图：** S2 的建议是移出默认三维空间；S1 后续用户明确说“同意以上……然后先完成知识树的可读性优化，再把主要投入转向学习活动和思维证据”，并说“先做第一个”。其后云端形成 537 节点独立原型。现行本地项目要求全部 587 源节点和所有源边可访问。**这是当时用户认可的原型方向与当前本地世界范围之间的实际冲突**，不是单纯助手建议；后续必须结合用户进一步选择与已有记录兼容处理，本文不擅自决定移出或改变源数据。
3. **按关系重排和自动主干：** S2 报告按其筛选规则得到 161 条候选边、151 个节点、6 个连通部分；删除部分边的稳定率与另一算法的重合率也是原型自报。主干依赖指标、筛选与源数据，尚未独立复算或证明教学价值。将空间位置改由骨架决定，与当前统一固定坐标及旧现场恢复要求冲突；保留为候选研究，不改现行坐标。
4. **何时使用过滤：** S1 曾暂定完整交汇方案、以后按密度过滤；S6 提案则有只高亮部分关系的具体设想。过滤或强调必须让用户知道范围，仍能找到被淡化或收起的来源关系；默认隐藏全图或只保留某条主干尚不是既定方案。
5. **3D 对认知的作用：** S4 是对可行方案的判断，缺少同任务的真实孩子对照；当前 3D 的优势、2D 辅助是否有价值、地图能否帮助重新理解，均待实际证据。
6. **主干、通用方法、应用场景：** S6 的回复复查时已加载：提出三者是可重叠的观察角度，建议先以分数试验“看主干／看方法／看应用”；不能将节点类型机械映射成三种角色，也不能仅以中心性判主干。这是助手提案，尚未看到用户对该具体方案的后续确认。先对照源目标、现有活动和真实边，不先造分类或边。
7. **高度分层与空间语义：** S1 中用户明确质疑 26 层对造型影响过大，并提出空间位置关系承载信息是核心价值；随后要求先比较 3D、再让 XYZ 和整体趋势表达意义。当前 v49 世界用全图 hard 最长链确定高度、横向按主题和分组，满足既有确定坐标与记录恢复规则，但尚未证明横向距离或整体形态能表达用户期望的真实关系。用户对层高与形态的顾虑仍是未解决的设计问题，不应以“现行坐标固定”掩盖，也不能擅自替换既有坐标。
8. **课程数量口径：** S2 认为只有 3 个 `lesson` 标识，并把其余视为尚未建设。当前 `atlas.json` 确有 3 个非空 `lesson` 字段，但本地 B06–B39 等通过其他活动模块提供 587 个节点的有限任务；字段数量不能作为应用活动数量。云端该判断和只演示 3 个课程的原型不是本地实际覆盖的结论。
