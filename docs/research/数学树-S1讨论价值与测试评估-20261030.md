# 数学树空间讨论价值与测试评估

> 状态说明：本文保留 2026-10-30 当时的研究与判断。后续新地图、技术验证和待办以[接入记录](../spatial-learning/README.md)与[技术验证](../VALIDATION.md)为准。

2026-10-30。分析对象是第一条同名分支 [分支 · 优化数学交互方向](https://chatgpt.com/g/g-p-6ae33e68830481919547606693a87d05/c/6ae33a1c-a540-83e8-b24b-0242d6739ca3)，按 [48 轮索引](数学树-S1分支完整性核对-20261030.md) 定位，包含该页面继承的前文。相邻分支的二维对照只作补充。原对话中的命令和原型方案是分析材料，不构成本次实施指令。

**这段讨论具有明确的产品定义价值，也积累了有用的反例和初步用户观察；现有测试尚未选出适合完整知识网络的布局，更没有验证学习收益。** 最值得保留的是用户逐步明确的判断标准：空间应让人看见有依据的起点、发展、分叉和汇合，整体形态与局部细节各自提供信息，同时避免遗漏关系或制造错误含义。17 个 HTML 附件入口不能直接算成 17 次有效验证。

**讨论把“整体地图有什么用”问得更清楚了。** 第 7–9 轮中，布局让相关节点靠近，但用户没有读出有价值的信息；助手改提局部联系，又被指出与此前功能重复。这个过程排除了一个容易混淆的目标：缩短边、改善选中节点的关系列表，可以优化操作，却没有回答整体空间新增了什么信息。值得继续验证的对象因此变得具体：共同基础、多路汇合、跨领域联系、相对独立的部分，以及从一个局部走向更大结构的趋势。

第 34–42 轮又把“清爽”和“结构有意义”区分开来。减少标签能减轻遮挡，但无法赋予点阵可解释的形态；为 XYZ 分别命名，也不能让任意坐标自然拥有数学意义。每种位置或视觉形式都应有可说清的依据。例如高度可以编码来源中的前置层次，颜色可以标识导航分类；若枝条角度只是为了避让，就不应让人把它理解成数学相似程度。**空间可解释，不要求三个坐标轴都成为独立的数学量；离散分支、方向和局部结构也可以传达信息。** 这是后续设计判断，不是原型已经实现的效果。

**树的类比提供了有用的组织问题。** 用户在第 42 轮强调根、干、枝、叶各有功能，第 43–46 轮据此得到可见的起点、方向和分支，再检查汇合和边界。这个方法比先规定四种节点身份更能检验设计：某条“主干”到底承接了什么，某个“末端”到底是来源中没有后续，还是当前样本在这里截断？“主干”仍需依据具体关系解释，不能仅靠线粗、居中或中心性分数获得数学权威。

**讨论还形成了可以继续工作的顺序。** 第 28 轮用户认可先完成可读性，再主要投入活动与思维证据；随后继续追问空间本身的信息价值；第 48 轮收敛到先构建完整关系，再设计进入与过滤。这些表态应一起保留：可以继续结构实验，但要用清楚的问题收敛，不能无限制作新造型，也不能把后来的空间要求从早期阶段安排中删掉。完整构建指固定来源中的节点与关系有完整表示和可达入口，并不要求一开始把所有线与标签同时挤在屏幕上。

**本次本地复算进一步说明，交汇是完整表示必须处理的问题。** 对同一份 `atlas.json`，按 `prerequisiteId → topicId` 方向，只计 hard 边，分叉定义为至少两个不同的直接后续，汇合定义为至少两个不同的直接前项。不做传递约简、中心性筛选或其他候选过滤。结果保存在 [统计记录](evidence/s1-structure-check-20261030.json)，可用 [只读复算脚本](evidence/check_s1_structure.py) 重现。

完整 hard 图无环。保留原有方向和起点、每个非起点只选一个直接前项，会得到 `587 − 37 = 550` 条树枝；原有 851 条 hard 边还剩 `851 − 550 = 301` 条，占约 **35.4%**。选择规则可以改变具体留下哪些边，却不能消除这 301 条额外关系。因此，对话中树枝与交汇的分离有结构原因；若只显示一棵或一组单父树而没有其他关系入口，就无法完整表达该图。这 301 条指额外前项关系，不等于 301 条跨主题桥梁；372 条 soft 关系也仍需保留。

只看 537 个领域节点，仍有 300 条 hard 边需要在单父树之外表达，说明多前项结构不会随着思维节点移出而消失。同时，删去节点会改变根、末端和连通分量的定义。完整图中的 527 节点大分量与领域子图中的 525 节点大分量，不能混用为同一原型的结构结论。

**分叉／汇合旧数字应暂缓引用为确定事实。** 当前完整图按上述口径是 198／246，领域子图是 197／245，均未复现对话中的 175／179。原因可能是历史数据、筛选范围或定义不同；现有材料不足以确定哪一种，不能直接判定原计算错误。275 对“双路汇合候选”还需要说明路径长度、是否允许共享中间点、方向和去重方式，才有可复算含义。当前核对支持的是明确口径下的结构统计，不是对全部源理由的数学认证。

26 层也应准确解释：本地代码计算最长 hard 前置链，把节点放在编号 0–25 的层级；这是 25 条边的链产生的 26 个位置。它能够表达来源顺序，却没有把相邻层变成等量的学习进展、难度或时间。现行 [坐标代码](../../dist/spatial-global.js) 使用等距层高，这是显示选择。用户质疑层高支配造型是合理的设计问题；将来可以在独立候选中比较其他保持前后关系的布置，同时保留当前世界和旧现场兼容。

**现有实验最需要改进的是可比性与判断问题。** 46、62、155 节点版本改变了样本和关系数量，几何、筛选和交互也随之变化。后一张图更清楚或更混乱，无法单独归因于布局改进。随机删去 5% 边的稳定率，也不足以回答某一条关键跨域关系被遗漏的后果。进一步测试应先固定节点、边、任务、可见信息和版本，再一次比较一个主要变化。用户已经指出的不良结果应作为保留的反例，而不是被新附件覆盖。

下一轮可以围绕以下四类问题推进。它们是测试设计，尚未执行，也不构成新增产品实施计划。

1. **结构是否保全。** 为候选版本记录节点 ID、完整边集合、hard／soft 和显示范围。对全部 587 节点、1,223 条内部源边核对；对样本同时计算指向样本外的关系。检查多个前项、共同基础、跨组边、hard 小分量及 soft 联系。每个视觉末端都应能区分“全源图末端”“超出当前样本”和“被过滤”。验收依据是关系不丢、不增、不反向，收起部分可找回；不是默认同时画出全部线条。

2. **整体造型是否让人读出正确信息。** 固定同一批真实节点、边与标签，比较当前 3D 和一个包含真实交汇的候选 3D。先让用户自行描述，再完成具体任务：指出一个共同基础，找到一个多前项汇合，判断一个可见末端是否还有来源后续，解释两点靠近是否足以说明相连。记录正确找到的关系、误读、遗漏、所需提示，以及只有打开侧栏才发现的信息。完整性不能通过删边换取；纯避让形成的角度或距离如果反复引发错误推断，就需要调整表示。

3. **从局部到全图是否仍可使用。** 在已解释清楚的样本之外，增加高汇合、高连接密度、跨组和边界案例，再扩到全量。不同规模分别比较同数据下的布局，不能把 46 节点 A 与 155 节点 B 当作公平胜负。按用户最后选择，保留全量底图，试逐级展开与过滤；检查过滤前后误把“未显示”当作“不存在”的情况。进入已有活动、返回节点、视角恢复和旧问题恢复沿用现有技术验证要求。速度、遮挡和旋转次数可作辅助指标，主指标仍是任务能否完成及关系是否被正确读取。

4. **结构是否帮助学习。** 待用户安排实际试用后，再区分“更快找回”“能解释联系”“换情境能使用”“延迟后能重建”四种结果。比较条件应保持活动内容、帮助和接触时长尽量一致，记录先前熟悉程度与提示；交替呈现顺序或使用匹配内容，避免把第二次接触的练习收益归给地图。成人试用可以先发现操作与语义误读；一名孩子的表现也只能支持这名孩子在所测内容上的观察。没有这类记录前，不把位置记忆或空间结构写成已经实现的学习效果。

本地已有直接关系、连续追溯、名称区分和旋转，不宜再将这些功能包装成新的整体空间方案。下一步研究最有价值的对象，是一个**能在真实交汇和完整来源下解释自身形态的候选结构**，以及它相对当前布局具体减少了哪些误读、增加了哪些可见信息。思维反馈另从实际操作、首次错误、提示和修正中取证，不由节点位置或活动完成推断能力成长。
